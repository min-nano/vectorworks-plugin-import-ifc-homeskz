# ホームズ君 IFC インポート（Vectorworks 2026 プラグイン）

**ホームズ君構造EX** が出力する木造軸組工法建築物の IFC ファイルを読み込み、Vectorworks
2026 の**ネイティブオブジェクト**（ストーリ・構造材・壁・スラブ・屋根面・シンボル・
ビューポート）へ変換して図面に配置する、C++ SDK 製のネイティブプラグインです。

メニューコマンドを 1 回実行するだけで、

- 階（ストーリ）とデザインレイヤ、通り芯、
- 基礎（立上り・底盤・人通口・地中梁）、床、横架材、柱、屋根組（垂木・野地板）、
- アンカーボルト・床束・火打・仕口のシンボル、柱・小屋束の記号、
- **伏図**（基礎伏図・各階柱梁伏図・母屋伏図）と**軸組図**のシート

までが一気に出来上がります。取り込んだものは編集可能なネイティブオブジェクトなので、
そのまま Vectorworks 上で修正・出図できます。

**macOS と Windows の両方**に対応します（Vectorworks 2026 が対応する 2 プラットフォーム）。

## 取り込むもの

| IFC 側 | 図面にできるもの | 配置先レイヤ |
| --- | --- | --- |
| `IfcBuildingStorey`（`…FL`） | ストーリ・ストーリレベル・デザインレイヤ | — |
| `IfcGridAxis` | 通り芯（`GridAxis`。軸名ラベル・基点バブル付き） | `共通` |
| 基礎梁（`IfcFooting`） | 立上り＝**壁**（人通口で分割／切り下げ、交点は壁結合、端部のキャップ） | `F-立上り` |
| 底盤（`IfcSlab` / `IfcFooting`） | 底盤＝**スラブ**（コンクリート／捨てコン／砕石の 3 層）。地中梁の位置は削り取り、同じ形の可視ソリッドで埋める | `F-底盤` |
| 床版（`IfcSlab`） | 床＝**スラブ**（床仕上げ＋床下地）。スキップフロアの段差は絶対 Z で表現 | `n-FL` |
| （床梁から合成） | ロフト（小屋裏収納）の床。ホームズ君は床版を出力しないので床梁が囲む領域から合成 | `R-FL` |
| `IfcBeam` / `IfcMember` | 横架材＝**構造材ツール**（土台・梁・桁／母屋・棟木／登り梁）。取り合いの食い込みを調整し、登り梁は屋根面へスナップ | `n-横架材天端`・`n-母屋`・`n-登り梁` |
| `IfcColumn` | 柱・小屋束＝**構造材ツール**。またぐレベルで span レイヤに分割。柱頭・柱脚金物の型名を構造材 ID に含む | `{from}to{to}-柱` |
| 屋根版（`IfcSlab`） | 垂木＝**構造材ツール**（既定 45×45＠455 以下）と野地板＝**屋根面オブジェクト**（12mm） | `n-垂木`・`n-野地板` |
| `IfcMechanicalFastener` | アンカーボルト（M12／M16）のシンボル | `F-アンカーボルト` |
| （大引から算出） | 床束のシンボル（910mm 間隔。立上りと重なるものは置かない） | `F-床束` |
| `火打:…` | 火打のシンボル（内角の二等分方向へ回転） | 横架材と同じレイヤ |
| （横架材・柱から導出） | 仕口のシンボル（受ける材のある端部。高さは横架材の天端に合わせる） | 横架材と同じレイヤ |
| （柱から導出） | 柱・小屋束の**断面記号**（柱＝×／小屋束＝／）と**伏図記号** | span レイヤ・`{to}-柱伏図記号` |
| — | **伏図**（基礎伏図・各階柱梁伏図・屋根版のある階の母屋伏図）。切断レベルで表示レイヤを絞り、断面寸法データタグとグラフィック凡例を載せる | シートレイヤ `1`, `2`, … |
| — | **軸組図**（柱と梁が通る通りごとの断面ビューポート）。断面寸法データタグ付き | シートレイヤ `A` |

### できあがる図面の構造

- **デザインレイヤ** … 階の接頭辞（最下階から `1`, `2`, …／最上階は `R`）＋レベル名で
  `1-FL` / `1-横架材天端` / `R-軒高` / `R-垂木` のように作られます。柱は
  `1to2-柱` のように**またぐレベル**でレイヤが分かれ、通り芯は `共通`、基礎は `F-…` です。
  レイヤの重ね順は「伏図で床・野地板が柱・梁を覆わない」ように並べ替えられます。
- **クラス** … 部材は `04構造-02木造-04梁桁-02軒桁` のような構造クラス、基礎は
  `04構造-01基礎-…`、スラブや壁の**構成層**は素材ごとのクラス（`z構成要素-コンクリート` /
  `z構成要素-合板` など）に分かれ、層の塗り・ペンは**クラス属性に従います**。断面の
  ハッチングや線をクラス側で変えれば、取り込んだ全部材に反映されます。
- **シートレイヤ** … 伏図が `1`（基礎伏図）から順に、軸組図が `A` に並びます。

高さは**ストーリレベルへのバインド**で持たせてあるので、階高を変えれば部材が追随します。

## 使い方

### 1. 図面側で用意しておくもの

プラグインは**既存のリソースを作りも書き換えもしません**。次のリソースは取り込み先の図面
（またはテンプレート）に用意しておいてください。**無くても取り込みは進みます**が、その要素は
置かれない（シンボル）か、既定の属性で描かれます（スタイル）。何が足りなかったかは完了
ダイアログの診断行に名前で出ます。

| 種別 | 名前 | 無いとどうなるか |
| --- | --- | --- |
| シンボル定義 | `アンカーボルト_M12` / `アンカーボルト_M16` / `床束` / `鋼製火打` / `仕口` | そのシンボルが置かれない |
| シンボル定義 | `柱伏図記号` / `束伏図記号` | 伏図記号が描かれない（断面記号は描かれる） |
| プラグインオブジェクトスタイル | `木質構造材_横架材` / `木質構造材_柱・束` | 構造材はスタイル無しで描かれる |
| 文字スタイル | `寸法(6pt)`（任意） | データタグの文字が既定の大きさになる |

断面寸法の**データタグ**とグラフィック凡例は、**スタイルを使わずに**——図面にスタイルを
作らず、既存のスタイルも当てずに——置かれます。中身（タグの寸法・凡例の並び）は
オブジェクトそのものが持つので、取り込みのたびに名前付きリソースが増えることはありません。
凡例のイメージの縮率は、その伏図の縮尺に合わせて置かれます。

### 2. 実行する

1. **ファイル ▸ IFC (ホームズ君) 取り込み…** を実行します
   （コマンドが見当たらないときは、下記「インストール」の最後の手順でワークスペースへ
   追加してください）。
2. IFC ファイルを選びます。
3. 進捗ダイアログに「いま何を・何件中の何件まで描いたか」が出ます。**キャンセル**で
   途中中断でき、そこまでに描いたオブジェクトは図面に残ります。
4. 完了ダイアログに、描いた要素が 1 行 1 要素の一覧で出ます。

完了ダイアログの読み方:

- 行が無い要素は、**解析の結果 0 件**だった要素です（基礎の無いモデルではアンカーボルト・
  床束の行が出ません）。
- `0/12 本` のような表記は、**命令はあるのに描けなかった**という意味です。直後の診断行に
  理由（リソースが無い・PIO を作れない等）が出ます。
- 最終行に取り消しの可否が出ます。

### 3. 取り消す

取り込み直後の **「取り消し」1 回**で、取り込みが作ったレイヤごと元の状態に戻ります
（編集メニューが「取り消し: ホームズ君 IFC 取り込み」と読めます）。

ただし次は戻りません（完了ダイアログがその旨を伝えます）。

- **クラス・ストーリ・レベルテンプレート**（リソースなので残ります。図面の見た目は
  取り込み前に戻ります）。
- **取り込み前から在ったレイヤへ描いた分**（同じ図面への 2 回目の取り込みなど）。その
  レイヤごと消すわけにいかないためです。

### 4. うまくいかないとき

- 壊れた IFC・途中で切れた IFC を読ませても Vectorworks は落ちず、エラーダイアログが
  1 通だけ出ます。本文に「詳細:」の行があります。
- **診断ログ**を出せます。dev ビルドは取り込みのたびに、stable ビルドは環境変数
  `HOMESKZ_IFC_TRACE` を設定したときだけ、一時ディレクトリへ `HomeskzIfcImport.log` を
  書きます（場所は完了ダイアログにも出ます）。フェーズごとに経過ミリ秒つきで 1 行ずつ、
  毎行フラッシュして書くので、無言で落ちた場合でも**最終行の直後**が原因箇所です。

## インストール

このプラグインは社内利用向けで、**未署名**（Apple Developer ID 署名なし、Vectorworks
開発者クレデンシャルなし）で配布されます。

**stable と dev の 2 つが共存できます。** 同じソースから、共存できる別名のプラグインを
ビルドしています。

- **`HomeskzIfcImport`** — *stable*。`main` からビルドされます。コマンド名は
  **IFC (ホームズ君) 取り込み…**。
- **`HomeskzIfcImportDev`** — *dev*。作業ブランチ／PR からビルドされます。コマンド名は
  **IFC (ホームズ君) 取り込み… (Dev)**。

出力名・リソース識別子・拡張機能 UUID がそれぞれ別なので、両方を同時に入れて使えます
（通常利用は stable、作業中のブランチを試すのは dev）。ビルドは
[GitHub のリリース](https://github.com/min-nano/vectorworks-plugin-import-ifc-homeskz/releases)
から取得します（stable は `stable` リリース、dev は `dev-<ブランチ名>` プレリリース）。

### macOS

プラグインの入れ物は `HomeskzIfcImport.vwlibrary` バンドルで、リソースはバンドル内に
含まれるのでこのフォルダだけで完結します。

1. **バンドルをローカルディスクに置きます**（iCloud Drive は不可 — iCloud が
   ダウンロード隔離フラグを付け直すことがあります）。置き場所は Vectorworks 2026 の
   ユーザフォルダ内の `Plug-Ins` ディレクトリです（Vectorworks ▸ 環境設定 ▸
   *ユーザフォルダ* から探せます）。

2. Gatekeeper がブロックしないよう、**macOS の隔離フラグを解除します**:

   ```sh
   xattr -dr com.apple.quarantine HomeskzIfcImport.vwlibrary
   ```

   CI ビルドは既に**アドホック署名済み**です（Apple Silicon がバイナリをロードするために
   必須。無料であり、Developer ID 署名ではありません）。それでも macOS が「壊れている」と
   言う場合は、自分で署名し直してください:

   ```sh
   codesign --force --deep --sign - HomeskzIfcImport.vwlibrary
   ```

3. **Vectorworks を起動します。** プラグインが未署名のため、Vectorworks 2026 は起動時に
   「不明／未署名のプラグイン」警告を表示し、既定で無効化することがあります。警告を
   了解してプラグインを有効化してください — 社内向け・クレデンシャルなしのプラグインでは
   想定どおりの挙動です。

4. **コマンドをワークスペースに追加します:** ツール ▸ ワークスペース ▸ 現在の
   ワークスペースを編集 ▸ *メニュー*。**ファイル** カテゴリの中に
   **IFC (ホームズ君) 取り込み…** があるので、メニューへドラッグしてください。

### Windows

プラグインの入れ物は `HomeskzIfcImport.vlb`（DLL）で、リソースは同名の別ファイルとして
隣に置きます（SDK の Windows での作法）。

1. **`HomeskzIfcImport.vlb` と `HomeskzIfcImport.vwr` を一緒に**、Vectorworks 2026 の
   ユーザフォルダ内の `Plug-Ins` ディレクトリへ置きます。2 つは同名・同フォルダである
   必要があります。自動アップデートも使うなら `HomeskzIfcImport.commit` と
   `vw-update.ps1` も一緒に置きます（配布 zip にはこれらがすべて入っています）。

2. **Vectorworks を起動します**（未署名の警告は macOS と同じ）。

3. **コマンドをワークスペースに追加します**（macOS の手順 4 と同じ）。

## 自動アップデート

プラグイン自身が、**Vectorworks の起動時に**ネイティブのダイアログでアップデートを扱います
（ターミナルを開く必要はありません）。

- **stable** … より新しい安定版ビルドがあるときだけ「インストールしますか？」と尋ねます。
  最新なら何も表示しません。オフラインやエラー時は静かに諦めます。
- **dev** … 使用するビルドをドロップダウンで尋ねます。先頭は現在ロードされているビルド
  （branch / commit）で、続いて他のブランチのプレリリースが並びます。キャンセルすれば
  何もしません。

コンパイル済みプラグインは起動時にしか読み込まれないため、インストールが成功すると
**「再起動」ボタン**をその場に出します。押すと、起動の完了後に Vectorworks を終了して
起動し直します（開いているファイルは通常どおり保存を確認してから閉じられ、保存ダイアログで
取り消せば Vectorworks は落ちません）。「後で」を選んだ場合は、次回の起動で反映されます。

仕組みの詳細（同梱スクリプト・再起動をヘルパープロセスに任せている理由・手動実行）は
[`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)「自動アップデートの仕組み」にあります。

## 既知の制限

- **ホームズ君構造EX が出力する IFC 専用**です。汎用の IFC には対応しません（既知の
  サブセット前提で最小の STEP リーダを組んでいます）。
- **床版の開口（階段の吹抜けなど）は塞がった形**で入ります。外形だけを読んでいます。
- **配筋は未対応**です（レコード `配筋` の設定は今後の課題。着手時は基礎の統合キーにも
  配筋を含める必要があります — [`docs/DEV-NOTES.md`](docs/DEV-NOTES.md)「残っている宿題」）。
- **ロフトの床は床梁から合成した近似**です（ホームズ君がロフトの床版を出力しないため）。
  床梁で囲まれた吹抜けは塞がり、骨組みが閉じていない部分は床になりません。
- **地中梁は「底盤を削り取るモディファイア」と「可視ソリッド」の 2 つ**で表現しています。
  スラブへ「足す」噛み合わせは、専用 API が実機で失敗するため使えません
  （[`docs/DEV-NOTES.md`](docs/DEV-NOTES.md)「打ち切った調査」）。
- **取り込み直後の伏図・軸組図は、1 回「更新」するまで床・野地板が柱・梁を覆って見えます。**
  VW はデザインレイヤを**高さの降順**（上にあるものが前面）で描くため、床仕上げ天端が
  構造天端より上にある以上、そのままでは床が手前に来ます。プラグインは伏図向けの重ね順
  （床・野地板を背面へ）を図面へ入れていますが、**それが絵に反映されるのは更新のとき**です。
  ビューポートを 1 回更新するか、ファイルを開き直すと正しく描き直されます
  （[`docs/DEV-NOTES.md`](docs/DEV-NOTES.md)「レイヤ・ストーリ・重ね順」）。
- **柱記号は柱を動かした瞬間には追随しません。** リセット・ファイルの再オープン・
  書き出し／印刷の直前に描き直されます（VW に「他の図形が変わったら再計算する」仕組みが
  ないため）。
- 断面ビューポート（軸組図）の範囲は、奥行きだけが無限で、**高さと長さは建物を包む実寸
  ＋余白**です（SDK に「無限」を指定する手段がありません。実用上は同じ見え方になります）。

## 開発者向け

- [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) — ソースの構成、ビルド（`VW_SDK_DIR`）、
  テストとカバレッジ、lint、CI とリリース、SDK ドキュメントの在り処、自動アップデートの
  仕組み。
- [`docs/DEV-NOTES.md`](docs/DEV-NOTES.md) — **開発メモ**。Vectorworks SDK の実測知見
  （実機でしか判明しなかった落とし穴）、設計の考え方、打ち切った調査、実装の経緯。
- [`tests/README.md`](tests/README.md) — テストの一覧・方針・何をテストしていないか。
- [`CLAUDE.md`](CLAUDE.md) — このリポジトリで作業するときの規約。

処理は **IFC 解析フェーズ（`src/parse/`）** と **VW 描画フェーズ（`src/draw/`）** に完全
分離し、両者は命令セット（`src/core/Document.h`）だけで接続します。`parse/` と `core/` は
**SDK を一切 include しない**ので、SDK 無しでコンパイル・単体テストできます。

```
IFC ファイル
   │  Phase 1: parse （SDK 非依存）
   ▼
Document（命令セット。プレーンな構造体の集まり）
   │  Phase 2: draw （VectorWorks SDK のみに依存）
   ▼
VectorWorks ネイティブオブジェクト
```
