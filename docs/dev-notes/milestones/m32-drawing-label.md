# 軸組図の図面ラベル（M32）

軸組図（断面ビューポート）1 枚ごとに、**真下の中央へ図面ラベル**を置いて図面タイトルを
出す。**図番と縮尺は出さない**（ご要望）。文字スタイル「図面ラベル(10pt)」は図面にあれば
当て、無ければ紙の 10pt を直接与える（データタグの「寸法(6pt)」と同じ流儀で、作らない）。

SDK の挙動（ラベルレイアウトの在り処・動的な文字列の式・ビューポートとの紐づき）は、
CLAUDE.md の方針 7 どおり**先に SDK リファレンスでプローブを回して確かめてから**実装した
（[Findings「Drawing Labels」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Drawing%20Labels.md)、
min-nano/vectorworks-developer-sdk-reference#149・#175）。本プラグインとして決めたことは 7 つ。

- **ラベルレイアウトは「タイトルと下線だけ」を複製して組み直す。** 図番・縮尺を消す
  パラメータは無く、レイアウトから落とすしかない。式（`#Drawing Label2#.#Title#`）は
  テキストが抱える隠れた状態で、新しく作ったテキストには持たせられない（Findings）ので、
  既定のレイアウトの**最初のテキスト＝タイトル**と**最初の線＝下線**を複製して新しい群へ
  入れ、渡し直す。文字では選ばない（テキストに名前は無く、見えている文字は UI の言語で
  変わる）。スタイルは作らないし当てない（CLAUDE.md 開発の基本方針 4）。
- **スタイル付きで作って組み直し、それから外す。** 実機 round 1 で、プラグインは当てて
  いないのに「図面ラベル - 図番」スタイルが当たっていた（スタイルの編集を開くと既定の
  レイアウトが出て食い違う）。`CreateCustomObject` は**ツールのスタイルを作った直後に
  勝手に当て**、しかも**既定のレイアウトはそのスタイルが配る**（スタイル無しで作ると
  レイアウトが空で何も描かない。Findings #175）。そこで「スタイル付きで作る → 組み直す →
  `gSDK->SetPluginObjectStyle(h, 0)` で外す」の順にした（外してもレイアウトは残る。
  `VWParametricObj::SetStyle(0)` は 0 を門で弾くので効かない）。ツールにスタイルが無い
  図面では複製する元が無いので、そのラベルは置かずに診断へ回す。
- **文字の大きさは「紙の上の mm」で与える。** round 1 ではタイトルが紙で 10pt より
  ずっと大きかった。`SetTextSize` の値は **pt ではなく mm** で、10 を渡すと 28pt になる。
  しかもレイアウトの文字は**容れ物（注釈）の縮尺を VW が掛ける**——寸法の
  `ovDimFontSize`（縮尺を自分で掛ける。M31）とは**逆**なので、同じ軸組図の中で作法が
  違う。紙の 10pt ＝ `core::pointsToMillimeters(10)` をそのまま渡す。文字スタイルは
  **当てたときのアクティブレイヤの縮尺が焼き付く**ので、当てる間だけ 1:1 のシート
  レイヤをアクティブにする（Findings「レイアウトの文字の大きさ」）。
- **ビューポートの注釈へ置き、Title は自分で書く。** 注釈に入れるとビューポートと
  リンクされ、利用者が後で図面タイトルを変えればラベルも追随する。ただし**置いた直後の
  Title は当てにならない**（Findings: 隣のビューポートのタイトルが入っていた）ので、
  注釈へ入れた後に命令の図面タイトルを書く。（後に図番（`Drawing`）も注釈へ入れる前と後の
  両方で書くようにした——書かないとラベルの自動の番号がビューポートの図番をすり替える。
  → [M25「図番が重なると Vectorworks が訊いてくる」](m25-test-separate-from-import/unattended-rounds.md#図番が重なると-vectorworks-が訊いてくる実機で発覚)）
- **位置は注釈空間で決め、置いてから測って動かす。** 寄せる点は「建物の最下点の、図の
  左右の中央」（`core::sectionLabelAnchor`）で、断面寸法タグ・寸法と同じ注釈空間の投影
  （`core::sectionAnnotationPoint`。タグが実機で合うことを確かめ済み）を使う。そのために
  投影を `parse/Tag` から `core/Document` へ移した（解析側と描画側の両方が使うため）。
- **図の下の寸法の外へ出す。** 軸組図は柱の位置の寸法（M31）を建物の真下に持つので、
  最下点の直下へ置くと寸法と重なる。ラベルの上端は「下に出る寸法の帯
  （`core::dimensionBand`）＋ 2mm」だけ下げる（`core::sectionLabelDrop`。寸法が無ければ
  2mm だけ）。
- **割り付けは変えない。** マスには断面の高さ範囲の下の余白（`kSectionHeightMargin`＝
  1000mm）と寸法の帯（M31）が含まれているので、ラベル（10pt の文字＋下線で用紙 5mm
  前後）はその残りに収まる前提にした。1/100 なら余白は用紙 10mm あり足りるが、縮尺が
  それより小さいとはみ出しうる。そのときは軸組図の「マスに収まらなかった」診断に出るので、
  実測を見てから割り付けにラベルの帯を足すか決める。**→ M35 でラベルの帯を足した**
  （高さ範囲の余白に収まらないぶんだけマスへ足す）。

**実機確認済み**（VW 2026 / macOS。PR #155 の 4019f2b・1/50 の軸組図 29 枚）: 各図の寸法の
下の中央にタイトルだけが出て、図番と縮尺は無く、スタイルは外れ、紙で 10pt。ビューポートの
図面タイトルを変えるとラベルも追随した。Findings が挙げる「作りたてのビューポートの注釈では
最初の 1〜2 本が容れ物の縮尺を拾わない」（#177）は、この取り込みでは起きなかった——もし
**最初の 1〜2 枚のラベルだけ見えない**ことがあれば、まずこれを疑う。
