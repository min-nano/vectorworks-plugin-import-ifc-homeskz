# レベル基準線の描き方の調整（M31 の後のご要望）

（伏図と軸組図へ寸法を自動で入れる（M31）は 4 ページに分けてある: [押さえ方の決め事](README.md) → [描画側の作法](drawing.md) → [実機で分かったこと](live-findings.md) → **レベル基準線の描き方の調整**）

- **名前の文字は寸法と同じ大きさ**（寸法規格の文字スタイルの紙の pt）。**高さの数値は
  描画しない**。▽ は**正三角形**で、高さは文字の 0.8 倍（「一回り小さい」）。
- **起点は左の高さの寸法列より外**（名前が寸法の文字と重ならない位置）、**基準線は起点
  から右へ**図の右端を用紙 3mm 越えるまで（それまでは建物の左端が起点で、線は左へ
  出ていた）。
- 既定のマーカーレイアウト（高さ `#Elev#` とストーリレベル名のテキスト・記号の
  ポリライン）は**全部消して**、名前と▽（線 3 本）を再生成する。レイアウトの長さは
  **用紙 mm** とみなした（Findings「Drawing Labels」の図面ラベルのレイアウトの実測を、
  同じプロファイルグループのマーカーレイアウトにも当てはめた。round 1 で縦の大きさが
  「文字＋隙間」の用紙 mm × 縮尺に合った）。
- **左へ出ていた線は PIO 自身の水平引出線**（実機とご指摘で分かった）。既定のレイアウトに
  線は無く、描画された中身は挿入点から左へ 5400（1/150 で用紙 36mm）のポリゴン 1 つ。
  **パスは持たない**（`GetCustomObjectPath` が nil。`SetCustomObjectPath` は反映されない）。
  **カスタム制御点**（既定 (0, 3000)）を (12399, 0) へ動かしても**ポリゴンは変わらない**。
  全 33 欄のどれにも −5400 は無く、線に関わりそうなのは `UseHorizontalLeader`（水平引出線を
  使用。既定 True）だけだった。そこで**引出線を切り、基準線はレイアウトの中に起点から右へ
  自分で引く**。**5343b0f の実機で確かめた**——`UseHorizontalLeader=False` で左のポリゴンは
  消え、描画された幅は狙い（起点〜右端＋用紙 3mm）と一致した（12399.2 / 12399.1）。
  **SDK リファレンスの Findings「Level Objects」へ返すこと**（パスを持たない・水平引出線は
  `UseHorizontalLeader` が制御する・カスタム制御点では動かない）。
- **同じ図の記号は ▽ の左端を揃える**（ご要望）。名前の幅は描画するまで分からないので、図の
  全記号のレイアウトを組んで名前を測り、いちばん広い記号で起点
  （`core::levelMarkStartX`）を決めて全部をそこへ置き直す。線の長さは
  `core::levelLineLength`。命令が持つのは図の左右の端と左の寸法の段だけ
  （`LevelMarkCommand::right` / `dimensionTier`）。
- **クラスと属性**（ご要望）: ▽ は閉じたポリライン（塗りが反映される）で「01作図-04記号-01一般」、
  名前の文字は「寸法」、基準線は「01作図-01線-01基準線-02一般」。どれも**全属性をクラスに
  従わせる**が、**矢印マーカーだけは除く**（`draw/DrawUtil` の `SetClassWithAttributes` の
  `withMarker=false`）。
- 記号は寸法の列より外へ張り出すので、軸組図の寸法の帯に 10mm を見込みで加えた
  （`core::kLevelMarkBandAllowance`）。
