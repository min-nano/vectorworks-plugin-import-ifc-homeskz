# 実機で分かったこと（M31）

（伏図と軸組図へ寸法を自動で入れる（M31）は 4 ページに分けてある: [押さえ方の決め事](README.md) → [描画側の作法](drawing.md) → **実機で分かったこと** → [レベル基準線の描き方の調整](level-lines.md)）

**実機で分かったこと（round 1）**:

- レベル基準線の名前（GL・1FL…）は**出た**。dev の検算が「名前が見つからない」と数えて
  いたのは、描画した文字がグループの入れ子の中にあって取りこぼしていたため（入れ子まで辿る
  ように直した）。
- **描画された高さが一定量ずれた**（GL が 4379.18・軒高が 10953.18。位置は合っている）。注釈の
  Y と描画される高さの間に一定のずれがあるので、描画された高さ（`Elevation`）を読んでずれを基準高さ
  （`RefElev`）へ加えて再描画する。量は決め打ちせず 1 本ずつ測る。
- **軸組図の寸法だけ値が出なかった**（伏図では出た）。`ovDimShowValue` を明示して立て、
  dev では寸法 1 本目の値表示・文字の大きさ・規格を記録に出して伏図と比べる。

**実機で分かったこと（round 2）**:

- **置いた直後は描画された高さが合っていた**（補正 0 個）のに、描画結果ではまだずれていた（GL が
  5103.18。round 1 と量が違う）。ずれは**ビューポートを用紙のマスへ動かした後**に生じると
  見て、動かした後にも測り直して基準高さで合わせる（`draw/Dimension` の
  `realignLevelMarks`）。記録の「補正」の 1 個目に時機（置いた直後／用紙へ動かした後）を
  添えるので、次の周でこの見立てが当たっているかが分かる。
- 軸組図の寸法は値表示 on・規格も同じなのに、**文字の図面上の大きさが伏図 105.8mm・
  軸組図 2.1mm**（作った直後に読んだ値）。伏図は 1/50 のデザインレイヤ、軸組図は直前に
  作ったシートレイヤ（1:1）がアクティブなまま作っているので、文字の大きさが作るときの
  レイヤの縮尺で決まり、1/50 の図の上で用紙 0.04mm になって見えないと疑っている。
  Findings「Dimensions」の「注釈空間は 1:1」と食い違うので、SDK リファレンス
  （issue #143）で調べてから直す。
  → **#143 で確定**（Findings の「1:1」は誤りだった）。寸法の文字の図面上の大きさ
  （`ovDimFontSize`）は作るときのアクティブレイヤの縮尺で焼き付き、注釈はビューポートの
  縮尺で描画される。規格の紙の pt を作った直後に読み、「pt × 25.4/72 × ビューポートの縮尺」を
  書き直す（`draw/Dimension` の `FitTextToViewport`）。アクティブレイヤに依らないので、
  伏図と軸組図で縮尺が違っても通る。

**実機で分かったこと（round 3）**:

- 用紙へ動かした後の測り直しで、描画された高さは**正しく出た**（116 個とも補正。GL は命令 0 に
  対し 5103.18 と出ていた）。
- ただし `Axis`＝`YAxis2DMode` の個体は**高さを注釈の Y から読むので、ドラッグで動かすと
  数値が変わる**。レベル基準線は本来ストーリレベルへ拘束するものなので、**Z 軸のまま
  ストーリレベルへ結ぶ（3 つ組）**へ切り替えると決めた（ご要望）。名前は今と同じ
  「GL / 1FL / 軒高」をレイアウトの差し替えで出す。
- **切り替えは SDK リファレンスの issue #141 の結論を待つ。** SDK の
  `CreateSectionViewport` で作った断面ビューポートの注釈では、3 つ組の個体の高さが `0` と
  描画される（UI 製の断面ビューポートでは出る。条件は調査中）。それまでは今の置き方のまま。
  → **#141 / #147 で確定して切り替えた。** SDK 製の断面ビューポートは断面の向き（1055）を
  持つのにビュー行列（1050）が単位行列のままで、注釈に縦の基準が無い。**ビューポートの
  更新をすべて済ませた後**に 1055 を 1050 へ複製し、置いたレベル記号を `ResetObject` すれば
  ストーリレベルの絶対 Z が入る（`UpdateViewport` は 1050 を戻すので、複製するのは最後。
  `draw/Dimension` の `finishLevelMarks` ＋ `draw/DrawUtil` の `CopySectionViewMatrix`）。
  Y 軸で読ませて補正していた処理（`RefElev` を加える・用紙へ動かした後の測り直し）は撤去し、
  描画された高さは読み戻して命令と照合するだけにした（高さは書けない出力）。
  **気を付けること**: 更新が 1050 を戻した後に個体を再生成すると高さが 0 に戻る（Findings
  「Viewports」）。利用者がビューポートを更新した後に記号を動かしたときにどうなるかは、
  実機で確かめる。

**実機で分かったこと（6041b56 の周）**:

- レベル記号は**ストーリレベルの高さで出た**（GL 0 / 1FL 612 / 2FL 3571 / 軒高 6374）。
- **軸組図の寸法の値はまだ出ない。** 繋ぐ前の直線寸法の文字の大きさは 264.583mm（1/125 で
  紙 6pt）と書けていた。**連続寸法へ繋いだときに中の寸法の大きさが、そのときの
  アクティブレイヤ（1:1）で再生成される**と見て、繋いだ後に中の直線寸法へ書き直す
  （`RefitChainMembers`）。書き直す前の値を記録へ残すので、見立てが当たったかは次の周で
  分かる。Findings の「`ovDimFontSize` を書けば直る」は単独の直線寸法での実測で、連続寸法は
  確かめられていない（SDK リファレンスへ調査を依頼する）。

**実機で分かったこと（683f566 の周）と、SDK リファレンス #157 の結論**:

- 連続寸法の中の文字の大きさを書き直しても（519 本）、軸組図の値は**出なかった**。
  利用者が OIP で文字スタイルを「寸法(6pt)」と明示すると出た（作った寸法は
  〈クラスの文字スタイル〉だった）。
- **#157 で確定**: 注釈に置いた寸法は〈クラスの文字スタイル〉のままだと値が描画されない。
  **`SetTextStyleRef` で文字スタイルを明示したときだけ**描画される（オブジェクト変数
  `ovDimTextStyle` へ番号を書く道は、読み戻しが同じなのに反映されない）。大きさは文字
  スタイルが決め、`ovDimFontSize` は触らない（触ると直線寸法と連続寸法で食い違う）。
  このため #143 の `ovDimFontSize` を書く手（`FitTextToViewport`）と、#155 の見立てで
  入れた連続寸法の中の書き直し（`RefitChainMembers`）は撤去した。
- **寸法規格が持つ文字スタイル**（`GetDimensionStandardVariable(index, dimStdTextStyle)`。
  組み込み規格は持たない）を、繋ぐ前の直線寸法へ `SetTextStyleRef` で当てる
  （`draw/DrawUtil` の `DimensionStandardTextStyle`）。
- **文字スタイルの大きさは図面上の長さ**として扱われ、ビューポートの縮尺で割られて紙に
  出る——「寸法(6pt)」をそのまま当てると 1/50・1/125 では紙の上でとても小さくなる見込み。
  紙で狙った pt にするには縮尺ごとの文字スタイルを作る必要があるが、**名前付きリソースを
  増やさない方針（CLAUDE.md 4）を優先し、作らないとご判断いただいた**（B 案）。実機で
  大きさがどう見えるかを確かめてから、次の手を決める。

**実機で分かったこと（73dc3a8 の周）と、SDK リファレンス #161 / #155 の結論**:

- 規格の文字スタイル「寸法(6pt)」を当てても、軸組図の値は**出なかった**（OIP では当たって
  見える）。OIP で同じ文字スタイルを選び直すと、紙 6pt で出た。伏図は変わらず出ている。
- **#161 で確定**: `SetTextStyleRef` は文字の大きさ（`ovDimFontSize`）を「文字スタイルの
  大きさ × そのときのアクティブレイヤの縮尺」で焼き直す。軸組図は 1:1 がアクティブなので
  紙で見えないほど小さい。OIP での選び直しは注釈（ビューポートの縮尺）の文脈で焼き直すので
  見える。**`ovDimFontSize` へ書いた値は `ResetObject` で引き直すまで描画結果に出ない**
  （#143 の手が機能しなかったのはこれ。読み戻しは書いた値を返すので気付けなかった）。
- そこで、文字スタイルを当てた後に `ovDimFontSize` ＝ 文字スタイルの紙の pt × 25.4/72 ×
  ビューポートの縮尺を書き、`ResetObject` で引き直してから繋ぐ。文字スタイルが明示して
  あれば、繋いで再生成された中の直線寸法も書いた大きさを保つ（〈クラスの文字スタイル〉の
  ままだと繋ぐときのアクティブレイヤで焼き直される。#155）。**文字スタイルは作らない**
  （B 案のまま）。

**実機で確かめること**: 寸法の段の間隔（用紙 8mm＋7mm）が詰まりすぎ／空きすぎないか・
外周の寸法が通り芯の符号と重ならないか・レベル基準線の名前の位置・基礎伏図の立上りに
沿う列の出し方（外側へ出す）。
