# 軸組図にする通りを選ぶ（M34）

軸組図は柱と梁の両方が通る通りを**全部**描画していた（M14）。要らない通りの軸組図を
消して回る手間を省くため、**描画する通りを取り込みの前に選べる**ようにした（ご要望）。
候補は「いま描画される通り全部」で、チェックを外した通りだけを飛ばす。

- **流れ**: ファイル選択 → 取り込み設定 → **通りの選択**（`draw/SectionPickDialog`）→
  取り込み。候補は `parse::buildSectionCandidates` が**取り込みと同じ `buildDocument`** で
  出す。切断位置は柱・横架材の命令から、映すレイヤはストーリの命令から決まるので全体の
  解析が要るが、大きなホームズ君 IFC でも 0.1 秒程度（フィクスチャ 5 本で 0.02〜0.09 秒）
  なので、選ぶために 1 度余分に回しても待たせない。**取り込みの解析と 2 回に分けるのは、
  `runImportRound`（本番と実機テストの共有部分）にダイアログを持ち込まないため**——解析の
  途中で問えば 1 回で済むが、テストの周は 1 枚もダイアログを出さずに回れることが
  `draw/ImportRun` の要件である（M25）。
- **実機テストも 1 周目で尋ねる。** 実機テスト（`draw/Feedback` の `runTestRound`）の
  1 周目は設定ダイアログの次にこのダイアログを出し、選んだ結果は設定と一緒に往復の記憶
  （`core::FeedbackSession` の `section.skip=` 行。1 本 1 行）へ入る。続きの周はダイアログを
  出さずに記憶から復元する（「続きの周にダイアログを 1 枚も出さない」）。**最初は本番の
  コマンドにしか追加しておらず、実機テストで試した利用者には「出ない」と見えた**——往復で
  確かめる機能は、往復の 1 周目にも同じ問いを置く。
  （「続きの周にダイアログを 1 枚も出さない」は M38 で「MCP の周にダイアログを 1 枚も
  出さない」に改め、メニューから押した続きの周は同じ条件でよいかを 1 度だけ尋ねる。
  M40 からは MCP が IFC を名指しして始める 1 周目もこのダイアログを出さず、全部描画する。→
  [設計の決めごと](../../development/live-test/design-rules.md)・[M40](m40-auto-first-round.md)）
- **設定は「外す通り」で持つ**（`core::ImportOptions::skippedSections`）。「描画する通り」で
  持つと、何も選んでいない既定が「1 枚も描画しない」になり、ダイアログを出さない経路
  （設定を出せなかったとき・M34 より前の往復の記憶）で軸組図が消える。
- **通りは図番で指す。** 図番は解析が方向をまたいで一意にする（`uniqueSectionNumbers`）
  ので、同じ IFC を解析し直せば同じ通りに同じ図番が付く。外すのは**一意にした後**
  （`parse::dropSkippedSections`）——外す前後で残る通りの図番が変わらない。
- **外すのは解析側。** 描画側で捨てるのではなく、そもそも命令を作らない（M20 の
  「取り込まない役割」と同じ考え方）。シートレイヤの割り付け・データタグ・寸法は
  残った軸組図だけで決まる。全部外せば軸組図のシートレイヤは作らない（空のものを先に
  作らない）。
- **毎回すべてチェックの入った状態で開き、前回の選択を覚えない。** 通り名（"X1" / "い"）は
  ファイルが違っても同じ綴りになりうるので、覚えると別の図面で黙って軸組図が欠ける。
- **設定ダイアログとは別の 1 枚にした。** 候補の本数はファイルごとに違い（数本〜30 本
  ほど）、設定ダイアログのコンパイル時の ID で組んだイベントマップと 2 つの形
  （サムネイル／名前）へ可変の行を混ぜると、確実に出すための作りを崩す。こちらは
  チェックと名前だけで、イベントを受けない（DDX で読むだけ）。使う SDK API は設定
  ダイアログで実機に出ているものだけに絞った。
- 外した通りは取り込みログの設定の段に「軸組図から外す通り: X1, Y2」と出る（外して
  いなければ「なし」）。
