# 図面枠をシートレイヤへ置く（M28）

取り込みが作るシートレイヤ（伏図＋軸組図）に、**図面枠（タイトルブロック）**を 1 つずつ
置けるようにした。決め事は 5 つ。

- **選ぶのは「スタイル」であって「置くかどうか」ではない。** 図面枠スタイルは利用者の
  図面ごとに名前が違い、**既定と呼べる名前が無い**——シンボルの役割のように「既定名を
  持ったまま取り込まない」という状態に意味が無いので、`core::ImportOptions` では
  **スタイル名の空文字ただ 1 つ**で「置かない」を表す（真偽と名前が食い違う状態を型の
  上で作らない）。既定は空＝置かない＝**この機能を入れる前と同じ振る舞い**。
  ただし**設定ダイアログの初期値は「置く」**——図面に図面枠スタイルがあれば、一覧の
  最初のスタイルを選んでチェックを入れた状態で開く（ご要望）。空文字は「置かない」と
  「まだ決めていない」を兼ねるので、ダイアログ側で「この起動中に OK で閉じたか」を別に
  覚え、決めたあとはその選択（チェックを外したならそれ）に従う。前回のスタイルがいまの
  図面に無いときも最初のスタイルへ寄せる（名前は図面ごとに違うので）。
- **設定ダイアログの候補は `GetSymbolDefSubType == 552`。** 他の行が「0＝普通のシンボル
  定義」を並べるのと表裏で、**同じリソース一覧から 2 通りに分けて抽出するだけ**（一覧を
  2 つ作らない）。値は SDK リファレンス
  [Findings「Symbols」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Symbols.md)
  の実測表にある。おかげで**図面に図面枠スタイルが 1 つも無ければその行だけが選べない**
  状態になり、他の行は普通に使える。
- **命令は文書に 1 つ。** 図面枠は「作ったシートレイヤすべてに 1 つずつ」で、IFC の中身で
  数も内容も変わらない。しかも**軸組図のシートレイヤは何枚できるかが描画するときにしか
  決まらない**ので、命令を 1 枚ずつ並べることがそもそもできない——`SectionSheetCommand`
  と同じ「枚数に依らない指示だけを持つ」形にした（`core::Document::titleBlockStyle`）。
- **スタイルが図面に無ければ 1 つも置かない。** スタイル無しの図面枠は「線だけの空の枠」に
  なり、図面を汚すだけで誰の役にも立たない。置かずに診断へ残すほうが良い（グラフィック
  凡例がスタイルを当てないのとは事情が逆——あちらは per-instance で中身を組めるが、
  図面枠の中身はスタイルにしか無い）。
- **置き場所は測って決める。** 図面枠 PIO の挿入点が枠のどこを指すかは分からないので、
  置いてから外形を測って**用紙の中心＝原点**へ寄せる（データタグ・凡例と同じ作法）。
  ビューポートを仕上げた**後に**置いて最背面へ回す（縮尺欄に縮尺を取得させるため。下記）。

**図面枠 PIO の登録名は `"Title Block Border"`（実機 round 1 で確定）。** SDK リファレンスの
`Findings/` に載っているのは「図面枠スタイルは subType 552」までで、**その型番号から
登録名を引く呼び出しは知られていない**。決め打つと「枠が出ない」という症状だけが残って
原因が名前だと気付けないので、当初は**候補を順に試して実際にオブジェクトを作れた名前を採り、
その名前を診断ログへ出す**形にした（PIO のパラメータ名を universal 名 → ローカライズ名の
順で引き直すのと同じ作法）。**実機フィードバックの 1 周で確定した**（VW 2026 / macOS。
PR #129 round 1 のログ「登録名 "Title Block Border"」）ので候補は 1 つに絞ってある。
**この知見はまだ SDK リファレンス側へ送っていない**（[「残っている宿題」](../open-issues.md)）。

**図面枠はビューポートを仕上げた後に置き、最背面へ回す。** 図面枠の「縮尺」欄は、作ったときに
用紙に載っているビューポートの縮尺を取得し、その後は勝手に取り直さない（ビューポートは 1 枚の
用紙に何枚でも置けるので、どれが変わっても枠は追わない）。当初は重なり順だけを考慮して
ビューポートより**先に**置いており、実機では**縮尺欄が 1:1 のまま**残った（OIP から手動で
更新すると正しい縮尺になる）。スタイルの流し込み（`UpdateStyledObjects`）でも、仕上げで
1 つずつ `ResetObject` しても直らなかった（PR #165 round 1）。そこで `finishTitleBlocks`
（伏図・軸組図とも縮尺を当て直し終えた後に呼ぶ）で**作り**、`InsertObjectBefore` で
シートレイヤの先頭の前へ差し込んで**最背面へ回す**（オブジェクト列は背面→前面の順。
デザインレイヤの並べ替えと同じ口）。描画の途中で控えるのは「どのシートレイヤに置くか」だけ
（`addTitleBlockSheet`）。回せなかった枚数は診断へ出す。

**「置けたか」は伏図と軸組図で別々に出す。** 枚数が違う（伏図は命令の数、軸組図は用紙の数）
ので、片方の行だけでは「作ったシートレイヤ**すべて**へ置けたか」が確かめられない——利用者の
求めがまさにそこなので、`titleBlockInfo` は `what` を取って 2 行並べる。そのために
`drawSections` にも `outInfo` を追加した（伏図は M18 から持っていた）。

**図面枠のぶんを用紙から差し引いてはいない。** 伏図・軸組図の縮尺と位置は印刷可能領域から
決めており（M18）、図面枠が占める帯は考慮していないので、枠とビューポートが重なりうる。
差し引くなら「置いて・スタイルを流し込んで・測った枠の内側」を `core::planLayout` /
`core::sectionLayout` へ渡す形になり、凡例の幅を実測で渡しているのと同じ手が使える
（[「残っている宿題」](../open-issues.md)）。
（軸組図は M35 でこの方法を取り入れた——割り付けの前に枠を仮に置いて測り、その内側へ並べる
（枠線の無い表題欄だけのスタイルなら、その高さを用紙の下から空ける）。伏図はまだ
印刷可能領域のまま。→ [M35](m35-section-layout.md)）
