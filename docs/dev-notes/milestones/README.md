# 実装の経緯（M0〜M43）

機能は「IFC 解析 → 命令セット → VW 描画 → 実機で目視確認」の 1 周が回る**縦切り**で、
1 マイルストーン＝1 要素ずつ積み上げた。**ソースコードのコメントにある `M<数字>` はこの
番号**を指す。番号は振り直さない（既存のコメント・PR 本文が参照している）。新しい区切りが
要るときは末尾に追加するか非整数（M9.5 等）にする。

| # | 要素 | 主な中身と、そこで分かったこと |
| --- | --- | --- |
| **M0** | 基盤整備 | 2 フェーズの骨組み・CMake 分割（無 SDK `MinNanoStructureCore` ＋ SDK 依存の本体）・最小 STEP リーダ・無 SDK テスト土台。手動ディスパッチ専用の CI デバッグ（`ci-debug`）もここで整備 |
| **M1** | 通り芯 | 最初の縦切り。`IfcGridAxis` → 区間ごとに 1 本・重複除去・センタリング・X/Y 判定 → `GridAxis` PIO |
| **M2** | 幾何の土台 | 配置行列（Gram-Schmidt で正規直交化）・押し出しソリッド・断面・boolean 辿り。描画なし＝テストのみ |
| **M3** | ストーリ | 階・ストーリレベル・デザインレイヤ。**レイヤ重ね順**の決定箇所（当初 per-viewport 上書きに委ねたが M13 で並べ替えへ差し替え。上書きは 2 度目の挑戦でも書けず打ち切り） |
| **M4** | 構造クラス判定 | 部材種別 → `04構造-…` クラスの純ロジック。STEP にも SDK にも依存しない |
| **M5** | 床板 | 形状先行①。各階 `n-FL` にスラブで床。ロフト床は床梁から領域合成、開口付き断面に対応、STEP の日本語エスケープをデコード。**床はスラブで描画する**（VectorScript 版の床ツールから意図的に変更） |
| **M6** | 屋根面・屋根組 | 形状先行②。屋根版から垂木・野地板を導出。`VWRoofFaceObj` と配置行列の作法がここで確定 |
| **M7** | 横架材 | 土台・梁・桁＋母屋・棟木・登り梁。天端中央線・食い込み調整・屋根面へのスナップ。**PIO のパスは 2D ポリライン**という作法がここで確定 |
| **M8** | 柱 | 管柱・通し柱・小屋束。span レイヤ（`{from}to{to}-柱`）分割。**鉛直パス＋バウンドの差の両方が要る**ことを 3 周かけて切り分け |
| **M9** | 基礎（立上り・底盤） | 立上り＝壁・底盤＝スラブ・基礎ストーリ。統合と自由端の延長、底盤の外面合わせ。**スタイルを作らない**方針をここで確定（一度作る形にしてから撤回） |
| **M10** | 基礎の高度化 | 人通口・壁結合（L/T/X）・地中梁。`ModifySlab` の調査打ち切り、`VWExtrudeObj` の平行移動、X 結合の分割仕様、キャップの明示——**実機由来の知見が最も多い区間**。配筋は保留（続き: [地中梁の可視ソリッドが幅方向にずれる](m10-ground-beam-shift.md)） |
| **M11** | シンボル置換 | アンカーボルト・床束・火打・仕口。**`VWSymbolObj` の 2 つの作法**（配置先レイヤへ入れ直す／非 nil を成功と見ない）。仕口の高さは `MoveObject3D` で合わせる |
| **M12** | 断面記号・伏図記号 | 柱・小屋束の記号を**自作 PIO**（`Extensions/ExtColumnMark`）で描画する。PIO を追加するときの 3 点と追随の限界は SDK リファレンス「Parametric Objects」にある |
| **M13** | 伏図・データタグ・凡例 | シートレイヤとビューポート、断面寸法データタグ（**軸組図にも載せる**）、グラフィック凡例。クラス表示・Project 2D の再生成・タグの 3 つの落とし穴。**傾いたタグの逃がし量はタグ自身の高さの半分**で、外接矩形（軸に平行）の高さを使うと文字の長さの sin 成分が混ざり、軸組図の登り梁のタグが材から大きく離れた（回転角から高さを戻す `core::rotatedRectHeight`。45 度近くは同じ図のほかのタグから借りる） |
| **M14** | 軸組図 | 柱梁の芯を通る通りごとに断面ビューポートを**新規作成**。範囲と表示の作法（奥行き 0＝無限・高さは実寸＋余白・レンダリングは隠線消去） |
| **M15** | 実行 UX・診断 | 完了文言の集約（`parse/Summary` の要素表 1 つ）・進捗ダイアログとキャンセル・`core/Trace`・例外処理・**Undo の一括化** |
| **M16** | 垂木の構造材化 | 垂木を軸組ツール（`FramingMember`）から**構造材ツール**（`StructuralMember`、構造用途＝垂木・断面基準点＝中下）へ移す。軒の出／差し込みのパラメータが無いので**パスを軒先まで伸ばし**、高さは他の木部材と同じくストーリバウンドで持つ |
| **M17** | 基礎の床付け | 捨てコン・砕石を施工に合わせて描画を分けた（[詳細](m17-footing-bedding.md)）。底盤の構成層は 2 層になり、地中梁の下は**押し出しソリッド**として敷く。傾斜部の帯が直交する地中梁へ食い込む問題は、帯の上端を 2 段階で切って解いた |
| **M18** | 用紙の割り付け | 用紙と建物の大きさから縮尺を自動決定（キリの良い分母だけ）。伏図は全図同じ縮尺・同じ位置＋凡例のぶんを引いてから縮尺を決める、軸組図は上下 2 段で複数シートへ整列。**余白は仮定せず印刷可能領域を読む**が、**用紙の位置は SDK から読めないので規約で決め打ち**（SDK リファレンス「Sheet Layers and Page Layout」） |
| **M19** | 完了ダイアログとログ | 完了ダイアログを「どのファイルを・成功したか・問題はあったか」だけに絞り、要素ごとの内訳はすべて診断ログへ移した。ログは**取り込みのたびに必ず開き**、見出し（リビジョン・日時・対象ファイル）と結果を持つ。ダイアログに**折り畳んだログ欄**を付けて、そのままコピーして報告できるようにした（作法は SDK リファレンス「Layout Dialogs」） |
| **M19** | 耐力壁 | 筋かい（`IfcMember` "筋かい…"）と面材（`IfcWall` "面材…"）を、**両端を柱に紐付けた線分 PIO**（`Extensions/ExtShearWall`）1 つずつで描画する。伏図は記号（三角・丸のシンボル）だけ・軸組図は形状（帯・面）という描画の分け方と、押し出し方向から壁の軸を取得する解析（[詳細](m19-shear-wall.md)） |
| **M19.5** | 共通化リファクタリング | 機能追加を止めて、複数モジュールへ複製されていたロジックを 1 か所へ寄せた（無 SDK 領域のみ。[「共通化で寄せたもの」](m19-5-consolidation.md)）。振る舞いは 1 点（同じページの Location 型チェック）を除き不変で、全フィクスチャのテストで担保 |
| **M20** | 端点を接合点へ | 構造材の端点を「材が止まる位置」から**接合相手の芯線上**へ移し、材の範囲は構造材ツールの端部オフセットで戻した（[「部材の端点は接合点（芯線の交点）に置く」](../design/member-placement.md#部材の端点は接合点芯線の交点に置く)）。描画される形は変えず、命令セットが**節点と部材**のモデルになる。端部オフセットの universal 名は SDK ヘッダに無いので候補で引き、解決できなければ診断へ手掛かりを出す |
| **M20** | シンボルの対応を選ぶ | 取り込み時に設定ダイアログを 1 枚出し、要素ごとに配置するシンボルを図面のシンボル定義から選べるようにした（`core::ImportOptions` が対応を持ち、解析側は固定名を持たない）。**名前ではなく図形で確かめられる**ことが要点。決め事は「[取り込み設定の決め事（M20）](../design/import-options.md)」 |
| **M21** | 殻と本体に割る | 成果物を「VectorWorks が読み込む殻」と「殻が自分で読み込む本体」に割り、本体だけの更新は再起動なしで反映されるようにした（「[殻と本体に割ってホットリロードする（M21）](m21-shell-and-payload.md)」） |
| **M22** | 配置をリリース側へ | ファイルの配置を、インストール済みの（＝古い）アップデータから**配布物と一緒に配られるインストーラ**へ移した。構成が変わっても手作業が要らない（「[配置の手順をリリース側へ移す（M22）](m22-installer-in-release.md)」） |
| **M23** | 実機確認の往復 | dev ビルドの取り込みが実機の結果を PR へ投稿し、次の取り込みの頭で新しいビルドを尋ねずに入れる**往復**をプラグインに回させた（入れ替えは必ず殻の側）。尋ねること・周の回し方・同梱スクリプトの落とし穴（bash 3.2・殻の ID から外す）・図面が戻っているかの測り方（「[実機確認の往復をプラグインに回させる（M23）](m23-feedback-loop/README.md)」。PR への投稿と自動の入れ替えは M38 で削除した） |
| **M23** | プラグインの位置付けと更新の起こし方 | 構造設計の機能をこの 1 つのプラグイン（表示名「みんなの構造設計支援」・`min-nano_structure`）へ集め、ユニバーサル名と UUID は据え置いた。更新の確認を起動時からメニューと取り込みの頭へ移し、再起動を SDK（`CloseAllFilesAndQuitVectorworks`）に頼めるようにした（「[プラグインの位置付けと、更新の起こし方（M23）](m23-update-trigger.md)」） |
| **M24** | 往復をモードレスのパレットで | 往復の駆動を殻の状態機械とモードレスの Web パレット（JS のタイマー）へ載せ、Claude の合図（PR のコメント）で止まるまで更新と取り込みが続くようにした（「[往復をモードレスのパレットで回す（M24）](m24-feedback-palette.md)」。M38 で削除した） |
| **M24** | MCP ブリッジ | メニューを実行している間だけ **Claude が図面を読める橋**を架けた（開発・デバッグ用）。受け渡しはスプール越しのファイル 2 つで、MCP そのものは同梱の Python サーバが担う（「[Claude と図面をつなぐ MCP ブリッジ（M24）](m24-mcp-bridge.md)」） |
| **M25** | 実機テストを本番から分ける | 本番の取り込みコマンドに織り込まれていた往復を、dev だけのメニュー「実機テストを実行…」（`Extensions/ExtTestMenu` ＋ `draw::runTestRound`）へ移した。共有するのは描画を行う `runImportRound` だけ。前の周の図の戻し方（取り消し・作業ファイル・レイヤ削除）と、無人の周を勝手に回さない・止めない作りもここ（「[実機テストを本番の取り込みから分ける（M25）](m25-test-separate-from-import/README.md)」。戻し方は M39 でテンプレートから開く形へ置き換えた） |
| **M26** | いま動いているビルド | 殻と本体に割った副作用で、別のブランチへ乗り換えても殻に焼いたブランチを名乗り続けていた。「いま」は**ディスクに入っているビルド**で判じる（`src/UpdaterParse.h` の `ResolveCurrentDevBuild`。「[「いま動いているビルド」はディスクに聞く（M26）](m26-current-build-from-disk.md)」） |
| **M27** | API の回数制限 | 往復が認証なしの GitHub REST の上限（IP ごとに 1 時間 60 回）に達した。GitHub を読む側（`vw-update`）にもトークンを付け（在り処は `scripts/vw-token.*` の 1 か所）、失敗の理由を必ず言う（「[往復が 1 時間 60 回の壁に当たる（M27）](m27-api-rate-limit.md)」） |
| **M27** | 柱が長さ 0 で描かれる | 命令もパスも指定どおりなのに実体を持たない柱が出る事故。原因は**渡した 2 点のパスが PIO 化（`CreateCustomObjectPath`）で退化する（長さ 0 になる）**こと——高さ基準は犯人ではなかった（実機 10 周で切り分け）。当座は**退化していたらパスを再生成して差し替える**（`SetCustomObjectPath`）で直したが、根本の直し方は**パスに Z を渡さない**（両端を同じ Z の 2D で渡し、高さはストーリバウンドだけで持つ）ことで、差し替える自己修復はのちに撤去した。打ち切った直し方・測り方（「[柱が長さ 0 で描かれる（M27）](m27-zero-length-column/README.md)」） |
| **M28** | 図面枠 | 取り込み設定に**図面枠スタイル**の行を追加し、伏図・軸組図の全シートレイヤへ図面枠を 1 つずつ置くようにした。スタイルは**当てるだけで作らない**（「[図面枠をシートレイヤへ置く（M28）](m28-title-block.md)」） |
| **M29** | 収まりの判定が周ごとにぶれる | 割り付けは同じなのに「用紙に収まらなかった」の件数が周ごとに動いた。測る側（再描画してから測る・タグを置いた後で測る・遊びの向き）を直し、はみ出した 1 枚目の実測を出したところ、**屋根面の勾配基準線が 1 スパンぶん飛び出していた**（`parse/Roof` の軒の軸）（「[「用紙に収まらなかった」が周ごとにぶれる（M29）](m29-fit-overflow-jitter.md)」） |
| **M30** | MCP ブリッジを常駐に・Vectorworks を起こす | 橋を**モードレスのパレットの JS タイマー**へ載せ替え、Vectorworks が動いている間は図面を触ったまま Claude が読めるようにした。Python サーバに **`vw_launch`**（Vectorworks を起動して橋が架かるまで待つ）を追加した（「[MCP ブリッジを常駐させる（M30）](m30-mcp-resident.md)」） |
| **M31** | 寸法 | 伏図（基礎・床・小屋・母屋）と軸組図へ**連続寸法**を、軸組図へ GL・FL・軒高の**レベル基準線**を、ビューポートの注釈として入れる。取り込み設定に**寸法規格**を追加し、空なら何も作らない。寸法の帯を用紙から引いて縮尺を選ぶ（「[伏図と軸組図へ寸法を自動で入れる（M31）](m31-dimensions/README.md)」） |
| **M32** | 軸組図の図面ラベル | 軸組図 1 枚ごとに、真下の中央へ**図面ラベル**（`Drawing Label2`）を置いて図面タイトルを出す（図番・縮尺は出さない）。SDK の挙動は先に SDK リファレンスで調べてから実装した（「[軸組図の図面ラベル（M32）](m32-drawing-label.md)」） |
| **M33** | 横架材の継手 | 同一直線上で横架材が突き付く箇所へ `継手` シンボルを 1 つずつ置く（`parse/Splice`）。位置は**材の端（端部オフセットを戻した点）どうしの一致**で見つけ、向き（+X が女木）は土台なら M12（座金付き）のアンカーボルト、それ以外は支点（下階の柱・小屋束・床束）から決める。IFC の `継手` 要素は向きを持たず土台に出ない（「[横架材の継手（M33）](m33-splice.md)」） |
| **M34** | 軸組図にする通りの選択 | 取り込み設定の次に、解析が軸組図にする通りを全部チェック付きで並べるダイアログを出し、**チェックを外した通りは軸組図の命令を作らない**。設定は「外す通り」の図番で持ち、既定の空が従来どおり（「[軸組図にする通りを選ぶ（M34）](m34-section-pick.md)」） |
| **M35** | 軸組図の割り付けを詰める | 注釈の帯を**出る辺にだけ**取り、上下の帯は高さ範囲の余白に先に収める（縮尺が 1〜2 段大きくなる）。図面枠を置くときは**枠を仮に置いて測り、その内側へ上寄せで**並べる（「[軸組図の割り付けを詰め、図面枠の内側へ並べる（M35）](m35-section-layout.md)」） |

| **M37** | 垂木の断面の指定 | IFC に垂木の寸法が無いので決め打ちしていた 45×45 を、取り込み設定で**全垂木に一律**に指定できるようにした（幅×せい、mm）。野地板の持ち上げもそのせいに従う（「[垂木の断面を一律に指定する（M37）](m37-rafter-section.md)」） |

| **M40** | 実機テストの 1 周目を無人で始める | MCP の `vw_run_test` に IFC とテンプレート（リポジトリの `tests/fixtures/Default.sta`）を渡すと、**記憶が無くても尋ねずに 1 周目から**走る。設定はテンプレートから開いた図面にあるもので組み（設定ダイアログをまだ決めていないときの初期値と同じ）、Vectorworks が起動していなければ MCP サーバが起こしてから頼む（「[実機テストの 1 周目を MCP から尋ねずに始める（M40）](m40-auto-first-round.md)」） |
| **M41** | ブリッジの時計を OS のタイマーへ | パレットの JS タイマーは、隠れている・背面に回ると 60 秒に 1 回まで間引かれ、図面が無い間はパレットが表示されない。殻の OS のタイマー（mac: `CFRunLoopTimer` / Windows: `SetTimer`）で受け付けるようにし、**起動しておくだけで、背面でも・図面が無くても**ブリッジが受け付けるようにした（「[MCP ブリッジの受け付けを殻の OS タイマーへ移す（M41）](m41-bridge-os-timer.md)」） |
| **M42** | MCP の呼び出しを占有で排他 | Claude のセッションごとに MCP サーバが起動し、同じ Vectorworks へ要求を書くので、片方の実機テストの最中にもう片方が更新・再起動しうる。Python サーバに占有を置き、**占有しているセッションだけがブリッジへ要求を送れる**ようにした。他は断られ、`vw_lock_status` の `wait` で解放まで経過を購読できる。占有は 60 分で、解放するときに実機テストを片付ける（図面を閉じ、一時ファイル・記録・報告を消す。`vw_test_cleanup`）（「[複数のセッションからの MCP の呼び出しを占有で排他する（M42）](m42-bridge-lease.md)」） |
| **M43** | 実機テストの条件を記憶しない | MCP の `vw_run_test` には IFC・テンプレートを**毎周渡し**、設定は図面から組んだ既定を `settings` で上書きする。プラグインが周をまたいで持ち越すのは**自分で保存した図面の記録だけ**にし、1 周目の条件・前の周の内訳・基準のレイヤの記憶と、報告の「前の周からの変化」をやめた。人が手で確かめるなら本番の取り込みで足りるので、メニュー「実機テストを実行…」も削除した（「[実機テストの条件を記憶しない（M43）](m43-no-remembered-conditions.md)」） |
