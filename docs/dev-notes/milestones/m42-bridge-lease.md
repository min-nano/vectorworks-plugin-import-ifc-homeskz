# 複数のセッションからの MCP の呼び出しを占有で排他する（M42）

**ご要望**: MCP が同時に複数のセッションから呼ばれうるが、Vectorworks は 1 つしか起動
できない。競合しない仕組みにし、他のセッションが使用中なら操作を断って、状況を購読できる
ようにしたい。占有は CI の往復を待てる長さ（60 分）にし、次の実行まで状態を持ち越さない
なら片付けてから解放する。解放するときの片付け（そのセッションが開いた図面を閉じ、一時
フォルダから消す）は自動にしたい。読み出しも占有の対象でよい。

**何が問題だったか。** `vw-mcp-server.py` は Claude Code のセッションごとに 1 つ起動し、
どれも同じスプールへ要求を書く。ブリッジ側は届いた順に処理するだけなので、

- 片方の `vw_run_test` の最中に、もう片方の `vw_update` / `vw_restart` が届けば、走っている
  周の後で本体が入れ替わり、Vectorworks が再起動する。
- 報告（`vw_test_report`）と診断ログ（`vw_log`）は「直近の周」のものなので、別のセッションの
  周の結果を自分の結果として読みうる。
- 1 周の最中はブリッジが受け付けを見送るので、他のセッションの要求は待ち時間を使い切って
  「応答がありません」になり、理由が分からない。

**どうしたか。** Python サーバに**占有**（lease）を置いた（`scripts/mcp/vw-mcp-server.py` の
`Lease`）。プラグイン側には手を入れていない——セッションを見分けられるのは Python 側だけで、
排他を Python 側で完結させれば殻・本体・ABI が変わらない。

- **ブリッジへ届く操作（プラグイン側の道具すべてと `vw_launch`）は、占有しているセッション
  だけが送れる。** 占有は最初の操作で自動で取る。読む道具も含めるのは、他のセッションの周の
  報告や描画途中の図面を自分の結果と取り違えないため。`vw_bridge_status` と道具の一覧の取得
  （`vw_tools`）は占有なしで通す（状況を調べる手段は残す）。
- **他のセッションが占有していれば、要求をスプールへ書かずに断る。** 返す本文には誰が
  （作業ディレクトリとブランチ）何を何秒しているか、いつ解放されるかが入る。
- **購読は `vw_lock_status` の `wait`。** 解放されるまで（`until: "change"` なら次の出来事まで）
  戻らず、その間の出来事（始めた・終えた・解いた）を返す。要求に `progressToken` があれば、
  出来事のたびに MCP の progress 通知も送る。
- **解放**は `vw_lock_release`・サーバの終了（stdin が閉じる・SIGTERM）・最後の操作から 60 分
  （`VW_MCP_LEASE_IDLE`）・持ち主のプロセスの消滅のいずれか。操作の最中は持ち主が 5 秒ごとに
  心拍を書き、120 秒途絶えたら停止とみなす（`vw_run_test` の 1 周は 30 分まで続くので、
  最後の操作からの時間では判定できない）。

**解放するときは片付ける。** プラグインに道具 `vw_test_cleanup`（`draw::endTestSession`）を
追加し、Python サーバが占有を解く前に呼ぶ。

1. 実機テストが保存した図面のうち開いているものを保存せずに閉じる（周の頭と同じ
   `CloseOwnedDocuments`。閉じる相手の判定は `isOwnedTestDocument` のまま）。
2. いま動いているビルドのブランチと、記憶が指すファイルを含む一時フォルダを消す
   （`core::sessionScratchDirs` が選び、安全弁は周の頭の片付けと同じ `removeScratchDir`）。
3. 記憶と報告を消す。報告を残すと、次に使うセッションが前の周の報告を自分の結果として読みうる。

閉じ残した図面・消せなかったフォルダがあれば記憶は残す（次の周の頭か次の片付けでもう一度
試す）。**持ち主が自分で片付けられずに解かれたとき**（時間切れ・異常終了・Vectorworks が
居なかった・1 周の最中だった）は占有の状態に「片付けが残っている」と記録し、**次に占有した
セッションが自分の操作の前に 1 度だけ片付ける**。1 度だけにするのは、そこで Vectorworks が
居なかったときにさらに引き継ぐと、その操作（`vw_run_test` など）が作った自分の図面を次の
操作の前に消してしまうため（Vectorworks が居なければ図面は開いておらず、残るのはファイル
だけで、PR が閉じれば周の頭で片付く）。

**決めごと。**

- **状態は 1 つの JSON（`<スプールの第 1 候補>.lease.json`）で、読み書きは OS のファイル
  ロック（`.lease.lock`。mac/Linux は `flock`、Windows は `msvcrt.locking`）の中でだけ行う。**
  ロックはプロセスが終われば OS が外すので、異常終了しても残らない。O_EXCL のロックファイルで
  作ると、持ち主が異常終了したときに「古いと判断して消す」処理どうしが競合する。
- **場所はスプールの第 1 候補の隣。** Vectorworks が起動する前（`vw_launch`）にも決まって
  いて、同じ利用者のセッションどうしで一致する必要がある（macOS の第 1 候補は利用者ごとの
  一時ディレクトリで、環境変数に依らない）。スプールの中に置かないのは、プラグイン側が開始時に
  スプールを掃除するため。
- **時間切れは 60 分。** CI の往復（push → dev ビルド → `vw_update`）を待つ間も占有し続け
  られる長さにする——その間に他のセッションが周を走らせると、待っていた側の記憶と図面が
  置き換わる。最初の版は 10 分で、CI の待ち（十数分）の間に解けた。その代わり**続けて
  使わないなら持ち主が `vw_lock_release` で片付けて解放する**のを運用とする
  （`docs/development/live-test/running.md`）。
- **片付けは周の頭の片付けと同じ安全弁を通る。** 消すものを選ぶ条件が「PR が閉じた」に
  「頼まれて終えた（いまのブランチ・記憶が指すもの）」が加わっただけで、`removeScratchDir` の
  安全弁（置き場の直下・目印の一致・ふつうのファイルだけ・`*.lck` が無い）は変えていない
  （CLAUDE.md「開発の基本方針」8）。
- **Windows ではプロセスの消滅を確かめない**（`os.kill(pid, 0)` は Windows では終了させる
  意味になる）。心拍と最後の操作の時刻だけで判定する。

**残っていること。** 持ち主のセッションが `vw_run_test` の途中で閉じられたとき、占有はすぐ
解けるが、Vectorworks の 1 周は最後まで走る。その間に取った他のセッションの要求は、1 周が
終わるまで「応答がありません」になる（`vw_bridge_status` の `busy_until` で分かる）。
