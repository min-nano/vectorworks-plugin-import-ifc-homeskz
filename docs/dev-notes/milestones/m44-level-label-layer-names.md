# レイヤ名をレベルの符号で揃える（M44）

**ご要望**: 階・高さとレイヤの対応を整理する。

1. **柱のレイヤにストーリレベルを当てない。** 柱は端部を上下の横架材天端のストーリレベルへ
   拘束しているので、柱のレイヤに専用のレベルは要らない。**ストーリだけ**を当てる。
2. **レイヤ名の高さの符号を、柱と横架材などで揃える。** M36 までは柱が `2to4-柱` のような
   通し番号、横架材・床が `3-横架材天端(FL-200)` のような高さの差で、対応が読み取りにくかった。
   横架材のレイヤ名は高さの差を書いているので、利用者がレベルの高さを変えると名前が
   食い違う。柱の通し番号は階と無関係に積まれるので、スキップフロアで伏図を分けると階の番号と
   かけ離れる。そこで、横架材のレイヤは `3±0-横架材`、柱のレイヤは `2-1_3±0-柱` とする。
   `2-1` の `2` は階、`-1` は基準のレベルからの段数。

**2 は実装した。1 は SDK の調査待ち**（下記）。

## 符号（`parse/Story` の `levelLabel`）

伏図レベル（M36。横架材の高さ 1 つ、またはまとめた高さの組）を**階の接頭辞と、その階の
標準の伏図レベルからの段数**で呼ぶ。

| 符号 | 意味 |
| --- | --- |
| `2±0` | 2 階の標準の伏図レベル（M36 の「標準」。その階の横架材天端にいちばん近い高さ） |
| `2-1` / `2+1` | 2 階の標準より 1 段低い／高い伏図レベル |
| `R±0` | 最上階（軒高）の標準の伏図レベル。接頭辞は従来どおり `R` |
| `2+0.5` | 2 階の標準と 1 段上の間（いちばん上なら屋根面）。屋根束の上端・登り梁の範囲に使う |

- **段数の表記は `core::planLevelStepText` だけが書く**（`±0` / `+1` / `-1` / `+0.5`）。
  `-0` / `+0` は書かず読まない（同じ段に 2 つの綴りを作らない）。
- **高さの数値はレイヤ名にもレベル種別にも書かない。** 標準でない伏図レベルのレベル種別は
  `横架材天端(-1)` のように段数の印を付ける（M36 は `横架材天端(FL-872)`）。高さは伏図の
  タイトル（`2階床伏図（FL-872）`）と設定ダイアログにだけ書く。
- 階の中の段は高さの昇順なので、段数は M36 の通し番号と 1 対 1 に対応する
  （通し番号＝その階の標準の通し番号＋段数）。**伏図の切断との比較は今も通し番号で行い**、
  レイヤ名の符号から引き直す（`parse/PlanLevel` の `labelOrdinal` / `parseSpanOrdinals`）。

## レイヤ名

| | M36 まで | M44 |
| --- | --- | --- |
| 横架材 | `2-横架材天端` / `2-横架材天端(FL-872)` / `R-軒高` | `2±0-横架材` / `2-1-横架材` / `R±0-横架材` |
| 軒桁・床・耐力壁 | `2-軒桁` / `2-FL(FL-872)` / `1-耐力壁` | `2±0-軒桁` / `2-1-FL` / `1±0-耐力壁` |
| 柱 | `1to2-柱` / `2to2.5-柱` / `1to3-柱` | `1±0_2±0-柱` / `2±0_2+0.5-柱` / `1±0_R±0-柱` |
| 登り梁（span） | `2to3.5-登り梁` | `2-1_2+0.5-登り梁` |
| 伏図記号 | `2-柱伏図記号` / `2.5-柱伏図記号` | `2±0-柱伏図記号` / `2+0.5-柱伏図記号` |
| 母屋・垂木・野地板 | `R-母屋` | 変えない（伏図レベルで分けない） |

- **横架材のレイヤは最上階も `横架材`**（`R±0-横架材`）。レベル種別は `軒高` のまま
  （`parse/Story` の `levelLayerSuffix`）。柱の `…_R±0-柱` と同じ符号で読めるようにするため。
- **伏図レベルで分けるレイヤは標準でも `±0` を付ける**（ご要望の `3±0-横架材`）。
  「段数の無い名前」と「`±0` の名前」が混ざらないので、段数を読み替える処理
  （`stripLevelStep`。仕口・継手・寸法・柱の上端の判定で同じ階の横架材を 1 群に扱う）が
  単純になる。
- **柱の符号は、その伏図レベルが属する階で書く。** from は柱が立つ伏図レベル、to は上端が
  届く伏図レベル（`spanLevelLabel`）。屋根束は届いた階のいちばん上の伏図レベルの半段上
  （`R±0_R+0.5-柱`。上階の無い最上階に立つ柱も同じ）。
- **登り梁の符号は材の階で書く**（`ordinalLabel`）。母屋伏図まで映す登り梁の上端は通し番号では
  次の階の伏図レベルと同じ値だが、`3-1` ではなく `2+1`（2 階のいちばん上の 1 段上）と書く——
  材は 2 階のもので、次の階のレベルに届くわけではないため。
- **レイヤ名の頭は必ず階の接頭辞**になったので、レイヤの階はどれも `layerStoryPrefix` で
  引ける（M36 では span レイヤだけ接頭辞が無く、データタグの注記と垂木が伏図レベルを介して
  階を引いていた）。

## 柱のレイヤをストーリだけに結ぶ（未実装・SDK の調査待ち）

今も柱のレイヤは専用のストーリレベル（レベル種別＝レイヤ名。`1±0_2±0-柱`）を持つ。
**ストーリにだけ結び、レベル「なし」にするには SDK の口が要る**:

- レイヤを作る手段として確かめてあるのは `CreateStoryLevelTemplate` ＋
  `AddStoryLevelFromTemplate`（＝レベルとレイヤを同時に生やす）だけ。
- `AssociateLayerWithStory(layer, story)` は【ヘッダ根拠】で、`AddStoryLevel` と組み合わせた
  ときに「レイヤ→レベルの紐付けが UI 上なし」になったという記録があるだけ
  （[Findings「Layers and Stories」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Layers%20and%20Stories.md)）。
- 柱の上端は `storyOffset = 1`（上の階）で横架材天端へバインドしているので、**レイヤが
  ストーリに属していることは必須**（素のデザインレイヤでは上の階を指せない）。

SDK リファレンスの
[issue #221](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/221) で、
レベル無しで階に結べるか・その上のバウンドが解決されるか・レイヤの高さと重ね順を調べて
もらっている。`Findings/` に反映されたら `draw/Story` で柱の span レイヤだけをレベル無しで
作る（`LevelCommand` に「レベルを作らない」ことを表す形が要る）。

## 図面への影響

- **取り込んだ図面のレイヤ名がすべて変わる**（基礎 `F-…`・通り芯 `共通`・母屋・垂木・
  野地板を除く）。既存の図面を取り込み直す運用は無い（取り込みは新しい図面に対して行う）が、
  利用者がレイヤ名で組んだ保存ビュー・ワークシートがあれば合わなくなる。
- 幾何・高さ基準・伏図に映るものは変わらない（名前だけ）。単体テストは命名の期待値だけを
  書き換え、伏図の表示レイヤ・耐力壁の柱・寸法の判定は同じ結果のまま通る。
