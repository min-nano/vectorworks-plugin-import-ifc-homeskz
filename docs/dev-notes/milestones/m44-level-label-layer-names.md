# レイヤ名をレベルの符号で揃える（M44）

**ご要望**: 階・高さとレイヤの対応を整理する。

1. **柱のレイヤにストーリレベルを当てない。** 柱は端部を上下の横架材天端のストーリレベルへ
   拘束しているので、柱のレイヤに専用のレベルは要らない。**ストーリだけ**を当てる。
2. **レイヤ名の高さの符号を、柱と横架材などで揃える。** M36 までは柱が `2to4-柱` のような
   通し番号、横架材・床が `3-横架材天端(FL-200)` のような高さの差で、対応が読み取りにくかった。
   横架材のレイヤ名は高さの差を書いているので、利用者がレベルの高さを変えると名前が
   食い違う。柱の通し番号は階と無関係に積まれるので、スキップフロアで伏図を分けると階の番号と
   かけ離れる。そこで、横架材のレイヤは `3±0-横架材`、柱のレイヤは `2-1_3±0-柱` とする。
   `2-1` の `2` は階、`-1` は基準のレベルからの段数。
3. （続けて）**耐力壁も柱と同じく `下端レベル_上端レベル` で表す。**
4. （続けて）**小屋束の上端の `R+0.5` を整数に揃える。**

**1〜4 とも実装した**（1 は SDK リファレンスの調査 #221 を待ってから。下記）。

## 符号（`parse/Story` の `levelLabel`）

伏図レベル（M36。横架材の高さ 1 つ、またはまとめた高さの組）を**階の接頭辞と、その階の
標準の伏図レベルからの段数**で呼ぶ。

| 符号 | 意味 |
| --- | --- |
| `2±0` | 2 階の標準の伏図レベル（M36 の「標準」。その階の横架材天端にいちばん近い高さ） |
| `2-1` / `2+1` | 2 階の標準より 1 段低い／高い伏図レベル |
| `R±0` | 最上階（軒高）の標準の伏図レベル。接頭辞は従来どおり `R` |
| `R+1` / `2+1` | その階のいちばん上の伏図レベルの 1 段上＝**その階の母屋のレベル**（下記）。屋根束の上端・母屋伏図・登り梁の範囲に使う |

- **段数の表記は `core::planLevelStepText` だけが書く**（`±0` / `+1` / `-1`）。
  `-0` / `+0` は書かず読まない（同じ段に 2 つの綴りを作らない）。表記は `+0.5` も読み書き
  できるが、取り込みが作る符号は整数だけ（ご要望 4）。
- **高さの数値はレイヤ名にもレベル種別にも書かない。** 標準でない伏図レベルのレベル種別は
  `横架材天端(-1)` のように段数の印を付ける（M36 は `横架材天端(FL-872)`）。高さは伏図の
  タイトル（`2階床伏図（FL-872）`）と設定ダイアログにだけ書く。
- 階の中の段は高さの昇順なので、段数は通し番号と 1 対 1 に対応する
  （通し番号＝その階の標準の通し番号＋段数）。**伏図の切断との比較は今も通し番号で行い**、
  レイヤ名の符号から引き直す（`parse/PlanLevel` の `labelOrdinal` / `parseSpanOrdinals`）。

## 母屋のレベル（小屋束の上端を整数に揃える）

M36 までは屋根束（小屋束・棟束）の上端を「届いた階のいちばん上の伏図レベル + 0.5」と
数え、母屋伏図はその上の `+ 0.75` で切っていた。符号にすると `R+0.5` になる。

そこで**通し番号を各階のあとに 1 つ空け、その番号をその階の母屋のレベル**とした
（`moyaOrdinal`。1FL・2FL（2 段）・RFL なら 1 / (2) / 3, 4 / (5) / 6 / (7)）。屋根束は
母屋を受けるので、上端は母屋のレベル（`R±0_R+1-柱`）。数の関係は M36 と同じに保ってある:

| | M36 | M44 |
| --- | --- | --- |
| 屋根束の span の to | いちばん上 + 0.5 | 母屋のレベル（いちばん上 + 1） |
| 母屋伏図の切断 | いちばん上 + 0.75 | 母屋のレベル + 0.25 |
| 次の階の最初の伏図レベル | いちばん上 + 1 | 母屋のレベル + 1 |

- 小屋伏図（いちばん上 + 0.25）では屋根束が断面で出て、母屋伏図では屋根束が切断より下
  （伏図記号 `R+1-柱伏図記号` で出る）、屋根を貫く主屋の柱（to が次の階）は母屋伏図に断面で出る
  ——M36 と同じ結果。
- **図番は通し番号から引かない**（番号が飛ぶので、伏図レベルの並び順で振る。parse/Sheet）。
- 伏図レベルが無いとき（単体テストで階だけを扱う）の番号は、階 s の標準が 2s+1・母屋が 2s+2
  （`standardOrdinalWithoutLevels`）。

## レイヤ名

| | M36 まで | M44 |
| --- | --- | --- |
| 横架材 | `2-横架材天端` / `2-横架材天端(FL-872)` / `R-軒高` | `2±0-横架材` / `2-1-横架材` / `R±0-横架材` |
| 軒桁・床 | `2-軒桁` / `2-FL(FL-872)` | `2±0-軒桁` / `2-1-FL` |
| 耐力壁 | `1-耐力壁` / `2-耐力壁(FL-872)` | `1±0_2±0-耐力壁` / `2-1_R-2-耐力壁` |
| 柱 | `1to2-柱` / `2to2.5-柱` / `1to3-柱` | `1±0_2±0-柱` / `2±0_2+1-柱` / `1±0_R±0-柱` |
| 登り梁（span） | `2to3.5-登り梁` | `2-1_2+1-登り梁` |
| 伏図記号 | `2-柱伏図記号` / `2.5-柱伏図記号` | `2±0-柱伏図記号` / `2+1-柱伏図記号` |
| 母屋・垂木・野地板 | `R-母屋` | 変えない（伏図レベルで分けない） |

- **横架材のレイヤは最上階も `横架材`**（`R±0-横架材`）。レベル種別は `軒高` のまま
  （`parse/Story` の `levelLayerSuffix`）。柱の `…_R±0-柱` と同じ符号で読めるようにするため。
- **伏図レベルで分けるレイヤは標準でも `±0` を付ける**（ご要望の `3±0-横架材`）。
  「段数の無い名前」と「`±0` の名前」が混ざらないので、段数を読み替える処理
  （`stripLevelStep`。仕口・継手・寸法・柱の上端の判定で同じ階の横架材を 1 群に扱う）が
  単純になる。
- **柱の符号は、その伏図レベルが属する階で書く。** from は柱が立つ伏図レベル、to は上端が
  届く伏図レベル（`spanLevelLabel`）。屋根束は届いた階の母屋のレベル（`R±0_R+1-柱`。上階の
  無い最上階に立つ柱も同じ）。
- **耐力壁は「立つ伏図レベル_上の横架材の伏図レベル」**（`1±0_2±0-耐力壁`。ご要望 3）。to は
  立つレベルより上の伏図レベル（階をまたいでよい）のうち、耐力壁の上端にいちばん近い天端のもの
  ——上端は上の横架材の下端（筋かい）か天端付近（面材）にあり、どちらもその横架材の天端に
  いちばん近い。上に伏図レベルが無ければ（最上階の耐力壁）その階の母屋のレベル。
  * 同じ伏図レベルに to の違う耐力壁のレイヤが並ぶので、ストーリのレベルの種別は**レイヤ名
    そのもの**（柱・登り梁の span と同じ）。高さは立つ伏図レベルの高さ（耐力壁の高さは
    レイヤ平面からの相対）。重ね順で前面へ回す判定は種別の接尾辞 `-耐力壁` で見る
    （core::desiredStoryLayerOrder）。
  * 伏図は from がその伏図レベルの耐力壁のレイヤをすべて映す（`shearWallLayersFrom`）。
- **登り梁の範囲は「映す伏図のレベル」の範囲**（両端を含む）。柱梁伏図だけなら
  `2-1_2-1-登り梁`、跨ぐものは `2-1_2±0-登り梁`、母屋伏図にも映すものは上端が母屋のレベル
  （`2-1_2+1-登り梁`）、母屋伏図だけなら `2+1_2+1-登り梁`。M36 の `o + 0.5` のような
  半端な値をやめ、整数の符号に揃えた。符号は材の階で書く（`ordinalLabel`）。
- **レイヤ名の頭は必ず階の接頭辞**になったので、レイヤの階はどれも `layerStoryPrefix` で
  引ける（M36 では span レイヤだけ接頭辞が無く、データタグの注記と垂木が伏図レベルを介して
  階を引いていた）。

## 柱のレイヤをストーリだけに結ぶ（レベルを持たない）

柱の span レイヤ（`1±0_2±0-柱`）は**ストーリにだけ結び、ストーリレベルを持たせない**
（オーガナイザで「ストーリ＝その階・ストーリレベル＝なし」）。M43 までは span ごとに
レベル種別＝レイヤ名の専用レベルを作っていたので、レベル種別の一覧が柱の span の数だけ
増えていた。

**作り方は SDK リファレンスの
[issue #221](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/221)
の実測どおり**（[Findings「Layers and Stories」](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Layers%20and%20Stories.md)
の「レベルを持たないレイヤを階に結ぶ」。`draw/Story` の `CreateStoryOnlyLayer`）:

1. `CreateLayer` で素のデザインレイヤを作る。
2. その階で未使用の**仮のレベル種別**を `SetLayerLevelType` で与える（1 つを使い回せる）
   ——素のレイヤ（種別 `''`）は `AssociateLayerWithStory` に弾かれる。仮の種別には
   **その階でこのあと横架材などのレイヤが使うレベル種別を借りる**（下記）。
3. `AssociateLayerWithStory` で階に結び、**`GetStoryOfLayer` の読み戻しで確かめる**。
4. `SetLayerLevelType(layer, "")` で種別を外す（階は残る）。

- **柱の高さは変わらない。** バウンドの宛先はバウンドに書いた種別（横架材天端）で決まり、
  入れ物のレイヤから要るのは**階だけ**（上の階を `storyOffset = 1` で数える）。レベル付きの
  レイヤと同じ値に解決され、階を動かせば追随する（Findings）。
- **結べなかったら作ったレイヤを消し、従来のレベル付きのレイヤで作り直す**（診断に枚数を
  残す）。階に属さないレイヤの上ではバウンドが同じ高さへ潰れ、長さ 0 の柱になるため
  （Findings「階に属さないレイヤの上では `eStoryObjectBound_Story` が…」）。
- レイヤの高さは**階の高さ**（FL。従来は横架材天端）。柱は高さをバウンドで決めるので
  効かない。
- レベルを持たないレイヤは VW の高さ順の自動整列に乗らないが、並びは
  `reorderStoryLayers`（`InsertObjectAfter`）が決めるので変わらない。スタック順は従来どおり
  その階のレベルより上段（`core::desiredStoryLayerOrder` が `StoryCommand::storyLayers` を
  levels の前に積む）。
- 命令セットでは `StoryCommand::storyLayers`（レベルを持たずに階だけに結ぶレイヤ名の列）で
  表す。軸組図の表示レイヤ（`parse/Section` の `sectionLayers`）もここから引く。
- **結ぶとその階に仮の種別のレベルができ、種別を外してもレベルは残る。** 当初は専用の種別
  `柱` を使っていたので、どのレイヤにも使われないストーリレベル `柱` が各階に残った。
  そこで**柱のレイヤをレベル付きのレイヤより先に作り**、仮の種別にはその階の levels の
  うちまだレイヤの無い最初の種別（横架材など）を借りる。残ったレベルには、あとでその種別の
  レイヤを `SetLayerLevelType` ＋ `AssociateLayerWithStory` で結び（テンプレート経由で作ると
  同じ種別のレベルがもう 1 つできる）、`SetStoryLevelElevation` で階内の相対Z を与える
  （`draw/Story` の `AttachLayerToLeftoverLevel`）。結べなければテンプレート経由で作り、
  診断に枚数を残す。

## 図面への影響

- **取り込んだ図面のレイヤ名がすべて変わる**（基礎 `F-…`・通り芯 `共通`・母屋・垂木・
  野地板を除く）。既存の図面を取り込み直す運用は無い（取り込みは新しい図面に対して行う）が、
  利用者がレイヤ名で組んだ保存ビュー・ワークシートがあれば合わなくなる。
- 幾何・高さ基準・伏図に映るものは変わらない（名前だけ）。耐力壁は span ごとにレイヤが
  分かれるので、スキップフロアではレイヤ（とストーリのレベル）の数が増える。全フィクスチャで
  変更前と命令セットを突き合わせ、増えたのはストーリのレベルと伏図・軸組図の表示レイヤの数
  だけであることを確かめた。
