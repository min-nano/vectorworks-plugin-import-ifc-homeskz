# 軸組図の割り付けを詰め、図面枠の内側へ並べる（M35）

ご要望は 2 つ——**図面枠と軸組図の下部が重なる**・**余白が多すぎるので詰めて縮尺を 1 段
大きく**。どちらも `core::sectionLayout` の見積もりが原因だった。

- **帯を四辺に取っていた。** M31 は「最も外の段の帯」を 1 つの値にして四辺すべてに取って
  いたが、軸組図の注釈は**左（高さの寸法 2 段＋レベル記号）と下（柱の位置の寸法＋図面
  ラベル）にしか出ない**。上と右の帯（実機の図で 1 枚あたり各 30mm 前後）はまるごと空きで、
  2 段・列の数だけ効いて縮尺を落としていた。いまは `core::sectionBands` が辺ごとに数える
  （`core::SectionBands`）。右は基準線が右端を越える `kLevelLineOvershoot` だけで、
  標準と違う高さの横架材の列（材の中央から右へ出す）は図の内側なので数えない。
- **下の帯と高さ範囲の余白を 2 度数えていた。** 断面の高さ範囲は建物の上下に
  `kSectionHeightMargin`（1000mm）を足してあり（M14）、図の下の寸法と図面ラベルは実際には
  その余白の中に描かれる（M32 の見立て）。それなのに帯をさらにマスへ足していた。いまは
  上下の帯を**まず余白（用紙の上では 1000 ÷ 縮尺）に収め、はみ出すぶんだけ**を足す。
  余白の用紙上の長さは縮尺で変わるので、縮尺の階梯を 1 つずつ組み直して収まりを見る
  （`fitScale` を使わない）。**ビューポートの外形が高さ範囲の余白を含むのか、映る図形だけ
  なのかは確かめていない**——どちらでもマスからはみ出さない側の見積もりにしてある。
- **図面ラベルを帯に入れた**（「残っている宿題」にあった件）。`kSectionLabelGap`＋
  `kSectionLabelAllowance`（6mm。紙の 10pt＋下線の見込み）。
- 帯が辺ごとに違うので、図は**マスの中央ではなく**帯の広い側の反対へずらして置く
  （`SectionLayout::viewportOffset` → `core::sectionViewportCenter`）。

試算（実機の A3・余白 0、建物 9880 × 高さ範囲 11000、帯 左 29・右 3・下 20）: 以前は
1/150、いまは **1/100**（`tests/CoreLayoutTests` の
`SectionLayoutTakesBandsOnlyOnTheSidesThatHaveThem`）。

**図面枠の内側へ並べる。** 印刷可能領域が用紙いっぱい（余白 0）の用紙では、2 段を用紙の
上下の中央に置くと下段の寸法・ラベルが図面枠にかかった。図面枠の大きさはスタイルと用紙で
決まるが、**枠はビューポートを仕上げた後にしか作れない**（M28 の縮尺欄）。そこで割り付けの
前に**1 つ仮に置いて外形を測り、すぐ消す**（`draw/TitleBlock` の `measureTitleBlockFrame`）。
並べる領域は「印刷可能領域」と「枠を `kTitleBlockInset`（5mm）内へ寄せた矩形」の重なり
（`core::insetFrameArea`）。

**表題欄の位置は測れない**（外形は枠線までで、表題欄が枠のどこを占めるかは SDK から
分からない。M28 の宿題のまま）。そこで枠線のある図面枠では段組みを**上へ寄せ**、余りを
すべて下へ回す（`SectionLayout::alignTop`）。**枠線の無い表題欄だけのスタイル**
（実機のもの）は下記 round 1 のとおり、帯の高さを下から空ける。

**記録を足した。** 診断ログに「軸組図の割り付け（mm）」の行（印刷可能・図面枠・並べる
領域・帯・建物・縮尺・マス・**実測の最大**）を出す。マスと実測の最大の差が、まだ詰められる
量である。

**実機で確かめること**: 縮尺が上がって隣の図・下段と重ならないか（「割り当てたマスに
収まらなかった」の診断）・図面枠の表題欄と重ならないか・仮に置いた枠が残っていないか・
伏図の図面枠の縮尺欄が変わっていないか（仮置きで `UpdateStyledObjects` をもう 1 回呼ぶ）。

**round 1（PR #176・A3・余白 0・建物 16250 × 高さ範囲 10754）で分かったこと。**

- **仮に置いた図面枠は 235 × 19mm を返した——測り違いではなかった。** 利用者の図面枠
  スタイルは**枠線を持たず、用紙の右下に表題欄の帯があるだけ**（実機の画面で確認）。
  それを「用紙を囲む枠」として内側へ絞ったので並べる領域が 225 × 9mm に潰れ、軸組図は
  1/200・1 列で用紙の中央に小さく並び、下段が表題欄に重なった。直し: 測った外形が用紙を
  囲む大きさ（幅・高さとも印刷可能領域の半分以上）なら従来どおり枠の内側へ上寄せ、
  そうでなければ**表題欄の帯とみなして、その高さ＋間隔 2 つ（29mm）を用紙の下から
  空ける**（`core::frameCoversPaper` / `core::reserveTitleStrip`）。表題欄が下にある前提で、
  左右のどこにあってもよいよう幅いっぱいに空ける。本置きの外形も診断ログへ出す
  （図面枠の行の「外形」）。
- **通り芯の符号（円）が建物の上へ出る**（画面で直径 8mm ほど）。上の帯に
  `kSectionGridBubbleAllowance`（10mm）を取る（通り芯のある文書だけ）。高さ範囲の余白に
  先に収めるので、1/100 以上では効かない。
- **下の注釈が見込みより 2.4mm 深かった**（29 枚中 19 枚が縦にはみ出し。1 枚目
  「測った 43.9×71.2 / 枠 113.2×68.8」）。図面ラベルの見込み `kSectionLabelAllowance` を
  6 → 9mm にした。
- この建物（16250 × 高さ範囲 10754）で下に 29mm を空けても 1/100・2 列に収まる
  （以前の割り付けでは 1/150。`TitleStripWithoutABorderReservesItsHeightAtTheBottom`）。
- 伏図は利用者から「良い大きさになった」（伏図の割り付けはこの PR で変えていない）。

**実機確認済み**（VW 2026 / macOS。PR #176 round 2 の 656f47e・A3・建物 16250 × 高さ範囲
10754）: 軸組図は 1/100・2 列 2 段・8 枚、マスからのはみ出し 0 枚（実測の最大 147 × 120 /
マス 195 × 121）。下段は右下の表題欄と重ならない。本置きの図面枠の外形も 235 × 19mm で、
仮測りと一致した。
