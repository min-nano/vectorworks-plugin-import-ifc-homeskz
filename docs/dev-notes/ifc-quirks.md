# IFC / STEP 側の癖

ホームズ君構造EX が出す IFC（IFC2X3）に固有の性質。**汎用 IFC 対応は非目標**で、この
既知サブセット前提に最小 STEP リーダ（`parse/Step`）を組んでいる。

## ホームズ君の出力仕様（公式の説明）

ホームズ君構造EX の IFC 出力時のヘルプ「構造EXから出力されるIFCファイルについて」に
書かれている前提。本プラグインの解析はこれと矛盾しない作りになっている。

- **形式は IFC2x3 Coordination View 2.0。** 実フィクスチャ 5 件すべてのヘッダが
  `FILE_SCHEMA(('IFC2X3'))` / `FILE_DESCRIPTION(('ViewDefinition [CoordinationView_V2.0]'),'2;1')`
  で一致する（`tests/fixtures/README.md`）。
- **出力される項目**: 通り芯・各階基準線・基礎（べた基礎・布基礎）・アンカーボルト・柱・筋かい・
  耐力壁・準耐力壁・梁・小屋束・床下地材・屋根版・柱頭柱脚接合部・横架材接合部。
  **出力されない**のは地盤改良工法・基礎ぐい（BIM 図面審査の入出力基準にはあるもの）。
  床束も出ない（下記）。
- **床下地材と屋根版の厚さは内部の固定値**（床下地材 28mm・屋根版 180mm）。実フィクスチャ
  でも `床版` の押し出しは全件 28.0、`屋根版` は全件 180.0 で、計算結果を反映した値ではない。
  そのため**どちらの厚さも作図に使わない**:
  * 床（`parse/Floor`）… 使うのは床版ソリッドの**下端の位置**（段差の検出）だけで、構成は
    床仕上げ＝FL − 横架材天端 − 24・床下地＝24mm 固定で組む（M5）。
  * 屋根（`parse/Rafter` / `parse/Roof`）… 使うのは屋根版の**平面（＝垂木下面。押し出しの
    基底面）と勾配**だけ。野地板の厚みは `kNojiitaThickness`、垂木せいは既定値で持つ（M6）。
- **接合部（柱頭柱脚・横架材）は直方体の簡易形状**で、名前に記号が入る（仕様表との照合用）。
  形状は当てにならないので、柱頭・柱脚金物は**型名（記号）だけ**を柱と XY 位置で対応付けて
  構造材 ID に載せる（`parse/Column`）。仕口（`parse/Joint`）は横架材接合部の直方体を
  読まず、部材の芯線から自前で求める。
- **梁せい計算・基礎構造計算が未計算のまま出力すると、部材の寸法が正しく出ないことがある。**
  許容応力度計算が済んでいれば、部材の仕様・寸法はその結果が優先される。取り込み側では
  判別できない（IFC に計算状態は載らない）ので、利用者向けに[「既知の制限」](../user-guide/known-limitations.md)へ
  書いてある。

## 読んでみて分かった癖

- **日本語の `Name` は ISO 10303-21 の拡張文字エスケープで出る**（`\X2\…\X0\` / `\X\HH` /
  `\S\c` / `\P?\`）。**デコードしないと名前による要素判別が一切通らない**（`床版` /
  `木梁:床大梁` など、ホームズ君の命名規約に全面的に依存している）。
- **IFC2X3 のファイルに IFC4 専用エンティティが混入する**（`IFCFOOTINGTYPE`）。スキーマ検証を
  する読み取り系はここで止まるが、**自前リーダは非正規エンティティもそのまま読める**ので
  除去は不要（本プラグインはそれらの型を参照しないので、グラフ上に残っていても無害）。
  `parse/Loader` はファイル読み込みだけを担い、サニタイズを持たない。
- **要素配置は `RelativePlacement` のみを使い、親を合成しない。** 親を合成すると階高が
  二重計上される。
- **開口付き断面（`IfcArbitraryProfileDefWithVoids`）がある。** 階段の吹抜けを持つ床版がこの型
  で出力され、未対応だと**床が丸ごと落ちる**（実データ 2 件で 2 階・3 階の床が入っていなかった）。
  現状は外形（`OuterCurve`）だけを読み、開口（`InnerCurves`）は無視する＝**床は開口を塞いだ
  形で入る**。
- **差演算（`IfcBooleanResult` / `IfcBooleanClippingResult`）の第 1 オペランドを再帰で辿る。**
  第 2 オペランド（削り取る側）は人通口の抽出に使う。
- **ロフト（小屋裏収納）の床版は出力されない。** 一方で小屋伏図には床梁が出るので、屋根階に
  床版が無いときに限り**床梁が囲む領域**を床の外形とみなす（`core/Region`）。近似であること
  ——床梁で囲まれた吹抜けは塞がり、骨組みが閉じていない部分は床にならない。
- **甲乙梁は Name の種別（`木梁:甲乙梁:…`）で床梁と区別できる。** IfcBeamType の
  PredefinedType は床小梁・床大梁と同じ `.BEAM.` なので、区別は Name だけが頼り。クラスは
  `04構造-02木造-04梁桁-05甲乙梁` に分ける（伏図で見え方を分けたいというご要望）が、
  ロフト床の合成では床梁と同じく床を受ける梁として扱う（`isFloorBeamClass`）。
- **小屋束の断面は当てにならない。** 直上に乗る母屋・棟木・登り梁の幅に合わせた正方形へ
  置き換える。
- **登り梁の入力位置が不正確**（軸勾配が屋根版より急・端部が受け材へ食い込む）。天端中央線を
  屋根面へスナップし、端部を受け材の面まで詰める。また端部が直切り（鉛直面）なので、
  天端は XY ずらし無しで **せい/(2·cosθ)** 持ち上げる（矩形前提の軸直交持ち上げだと天端が
  垂木下面に届かない）。
- **登り梁が隣の屋根面へ吸われる。** 下屋・庇のように細い屋根版が主屋根の外形に接して並ぶと、
  登り梁の端点（受け材の芯まで伸びている）が主屋根の外形にもかかる。スナップ先の屋根面は
  **中点を内包する面を先に全面から探し、無いときだけ端点で探す**（`parse/Noboribari` の
  `roofPlaneFor`）。以前は面ごとに中点・端点をまとめて見ていたため、並びが先の主屋根が
  始端をかすめただけで選ばれ、又ち通りの 2 階小屋の登り梁が主屋根の高さ（272.27 mm 上）で
  描かれた。
- **基礎梁は底盤の底面までの全高でモデリングされている。** 立上りの下端をさらに下げる必要は
  無い（下げると底盤の下へ突き出すだけで意図と逆になる）。深さの差（スキップフロアなど）は
  IFC の実形状のまま残す。
- **地中梁の断面は立上りの外面に片側の垂直面が付き、内側へ広がる逆台形**（ハンチ。例:
  `(0,0) (-200,0) (-380,150) (0,150)` で配置原点が立上りの外面）。壁芯に対して中心を
  合わせたいなら、それは IFC の実形状から意図的に変える話になる。
- **人通口は実寸法でモデル化されている**（長さ補正しない）。立上りソリッドから天端の下方へ
  削り取った別ソリッドとして出るので、「天端まで届き底面には届かない」削りだけを拾う
  （端部が他材で削られた全高の差演算を人通口と誤認しないため）。
- **床束は IFC に出力されない。** 大引の下へ 910mm 間隔で決め打ち配置する（継手で分断された
  大引は 1 連へ統合し、端部は受けている支持材の芯にする）。
- **横架材を受ける束（小屋束・柱と別の鉛直材）も IFC に出力されない。** 階の中間の横架材を
  持つモデル（RFL の中に Z=5540 の床梁が並ぶもの）で調べたが、鉛直材は `IFCCOLUMN` の
  「柱:N_N」（型 `木柱:…`）と「小屋束:N_N」（型 `小屋束`・ObjectType `STANDCOLUMN`）だけで、
  束を名乗る型・名前・プロパティ・金物は無く、縦向きの `IFCMEMBER` / `IFCBEAM` も無かった。
  中間の床梁の上に立つ鉛直材は小屋束として出ている 1 本だけ（登り梁を受ける）。床束と違って
  置き方の決まりを機械的に推測できないので、**この機能は保留**にした（再開するなら、束が
  ある位置をホームズ君の画面で確かめてから推定の決まりを決める）。
