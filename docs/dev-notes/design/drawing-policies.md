# 描いた結果に対する 5 つの方針

1. **空のものを先に作らない。** 描画対象の無いレベル・レイヤ・凡例は作らない。ストーリの
   レベルは「その要素の命令が実際にあるか」で判断して追加する。空レイヤが図面に残ると、
   利用者はそれが失敗なのか仕様なのか判断できない。
2. **図面の既存リソースを書き換えない・増やさない。** スラブ／ウォールスタイルも
   データタグスタイルも**作らず**、構成層・基準面・タグレイアウトをオブジェクトへ直接
   与える。唯一の例外は耐力壁の伏図記号のシンボル定義で、作ってよい条件は
   CLAUDE.md「開発の基本方針」4 にある。スタイルを作る形は、取り込みのたびに名前付き
   リソースが増え、しかも undo で消えないため、どちらも一度採用してから撤回した。
3. **決定性を守る。** エンティティの列挙順に依存しない結果を出す。ソート・集約は明示的に
   行い、同値のときの順序も決めておく（`#id` 昇順など）。テストは全要素で決定性を確認している。
4. **1 要素の欠損で全体を止めない。** 想定外のエンティティ・解決できない幾何はスキップして
   次へ進む。例外は `parse/` 内部の局所処理に留め、フェーズ境界は値で返す。SDK
   コールバック（`plugin_module_main` / `DoInterface`）へ例外を漏らさない。
5. **診断は「異常だけ」を出す。** 平常時にも出る診断は削除する（[「診断・完了報告の方針」](diagnostics.md)）。「問題あり」の根拠になるのは**起きては
   いけないこと**だけで、平常の内訳はログにだけ出す。完了ダイアログには件数も出さない（M19）。
