# 用紙の割り付けの決め事（M18）

用紙と建物の大きさから縮尺・配置を自動で決める。用紙の読み取り（単位の癖・印刷可能
領域）と「置いた後に測って動かす」作法は SDK リファレンスの
[用紙（シートレイヤ）と割り付け](https://github.com/min-nano/vectorworks-developer-sdk-reference/blob/main/Findings/Sheet%20Layers%20and%20Page%20Layout.md)
にある。このプラグインとしての決め事は次のとおり。

- **縮尺は「印刷可能領域に収まる中で最も大きい図」を階梯から選ぶ**（`core::fitScale`）。
  階梯は 1/200・1/175・1/150・1/125・1/100・1/75・1/50・1/30・1/25・1/20・1/15・1/10・1/5
  のキリの良い値だけで、どれにも収まらなければ**いちばん小さい図**を選ぶ
  （はみ出すくらいなら小さく描画する）。
- **伏図は全図が同じ縮尺・同じ位置**（用紙をめくっても図が動かないため）。位置は
  「外形の中心を用紙の中心へ」ではなく、**建物の中心が常に同じ点へ来る**ように置く。
  ずらす量は「その伏図に映る範囲の中心 − 文書全体の中心」を縮尺で割ったもの。
  伏図ごとに表示するレイヤが違えば図の中身の範囲も違うので、外形の中心で揃えると
  ページごとに建物がずれる。
- **縮尺は凡例の幅を引いてから決める。** 凡例を置けなくなるくらいなら図を 1 段階小さく
  描画する、が決まりごと。引く幅は定数ではなく**実測した凡例の幅**で、`draw/Sheet` は
  **2 巡**する（1 巡目は仮の縮尺で図と凡例を作って幅を測り、2 巡目で確定した縮尺を設定し
  直す。`ApplyViewportScale` は縮尺が実際に変わったときだけ——更新は処理が重い）。凡例の
  大きさは中身が流し込まれるまで確定しないためである。用紙いっぱいで縮尺を決めて凡例は
  置き場所だけで避ける、という形も一度試したが、建物がギリギリの大きさだと凡例を置く
  スペースが残らない（凡例も図面の一部で、重なると読めない）。
- **縮尺を決めた 3 つの値（印刷可能領域・凡例の幅・建物の広がり）は結果として残す。**
  `draw/Sheet` は「伏図の割り付け（mm）: 用紙 … / 印刷可能 … /
  凡例 … / 建物 … → 用紙上 … / 縮尺 1/N」の 1 行を診断ログへ出す（平常でも出る記録なので、
  M19 からは完了ダイアログではなくログだけ）。M31 からは**寸法の帯**（`core::dimensionBand`）
  も用紙から引いてから縮尺を選ぶが、この行には出ていない。命令の座標に
  現れないもの（通り芯の丸など）のぶん実際の図は見積もりより大きくなりうるので、
  **はみ出し・重なりは描画側が実測して診断へ残す**。
  ローカル確認の場で分かるのは結果の縮尺だけなので、これが無いとどれが影響したのか
  切り分けられない（実際に「1/50 のはずが 1/75 になる」で調査が止まり、建物が
  18.07 × 13.52m あって当時の割り付けでは 1/50 が入らない——実装も測り方も正しい——と
  分かるまで往復した）。
- **軸組図は上下 2 段**になる縮尺を選び、1 段の枚数は用紙の幅から決める。入りきらない
  ぶんはシートレイヤを追加し、タイトルを "軸組図(1)" … と連番にする。**何枚に分かれるかは
  用紙が分からないと決まらない**ので、命令セットが持つのは「番号の始まり（伏図の続き）と
  タイトルの基」だけにした（`core::SectionSheetCommand`）。用紙の大きさを読むには 1 枚目の
  シートレイヤが要るので、**先に 1 枚用意してから**割り付けを決め、タイトルは本番の
  ループで付け直している。注釈の帯を辺ごとに取ることと、図面枠の内側（または表題欄の帯の
  上）へ並べることは M35 で追加した（[軸組図の割り付けを詰め、図面枠の内側へ並べる](../milestones/m35-section-layout.md)）。
- **余白の解釈は `core::resolvePageMargins`（無 SDK）に置いてある。** 読むのは SDK の
  仕事だが、**読めた数字をどう解釈するか**——インチか mm かの突き合わせ・0 の扱い・
  負値の棄却——は計算でしかないので、描画側から切り離して `CoreLayoutTests` で
  テストする（CLAUDE.md「描画側から切り離せる純計算」）。
