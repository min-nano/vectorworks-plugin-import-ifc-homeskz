# 報告の読み方（Claude 向け）

報告（`vw_test_report`、または `vw_run_test` の応答の `report`）は、ローカルの Vectorworks が
自動で組んだ Markdown です。**人は 1 文字も書いていません。数字と診断ログしか無く**、
描画結果がどう見えたか（所見）は利用者がチャットへ直接書きます。読む順序は:

1. **「図面の状態:」を確認する。** 正常なら「取り込み前の状態へ戻してから実行されています」に
   なります（M39 からは毎周テンプレートから開いた新しい図面へ描画するので、崩れるのは
   テンプレートそのものが汚れていたときです）。「前の周の図が残ったまま重ねて描きました」なら
   **図面の用意に失敗している**（「準備:」の行に何をしたかが出る）ので、**描画結果は
   二重になっている——その破綻をそのまま実装の原因としない**でください。数字は重なっていても
   変わらないので、この行が唯一の手掛かりです。1 周目は基準を採ったことしか言いません
   （「この顔ぶれを基準にします」か   「まっさらな図面から取り込みました」。テンプレートにもとから在るレイヤを「戻し忘れ」と
   読み違えないため。M23 で一度そう読み違えた）。
2. **「前の周からの変化」を確認する。** 数字が動いていないなら、修正が反映されて
   いません（`vw_update` の応答の `payload_commit`・`vw_run_test` の応答の `commit`・報告の
   見出しのビルドが、push したものか確かめる）。
3. 要素の内訳・注意・診断ログ（`vw_log` で全文）で裏付けを取る。
4. **命令の数が合っていても描画結果が破綻していることは普通にある**と常に疑う。怪しければ、
   「3 階の梁の天端が基準面と合っているか」のように**描画結果を見て答えられる形**で人に確かめて
   もらいます。

**頼んでよいのは「再起動の保存の確認に応えてください」「描画結果を見てください」だけ**です
（1 周目も `vw_run_test` に `ifc` と `template` を渡して自分で始める。M40）。ファイルを
選び直す・ログを貼る——このどれかを頼みたくなったら、それは仕組みが壊れている合図なので、
頼む前に直してください。

**実機テストは実機確認の代わりになりません。** 描画に触れる PR をマージしてよいのは人が
「確認できた」と言ったときだけです（[`CLAUDE.md`](../../../CLAUDE.md)「開発プロセス: PR とマージ」）。
